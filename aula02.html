🎯 Objetivos da Aula

Compreender o que é HTML — entender por que ele é a espinha dorsal de toda página na web e qual é o seu papel ao lado do CSS e do JavaScript.

Conhecer a estrutura básica de um documento — dominar o esqueleto <!DOCTYPE>, <html>, <head> e <body> e saber o que vai em cada parte.

Aprender as tags essenciais — estudar todas as tags usadas na página tributo ao Pearl Jam: de headings a imagens, links, listas, seções e footer.

Construir a página do Pearl Jam — entender cada bloco do index.html e como eles se encaixam para formar um site real e completo.

Publicar com GitHub Pages — unir Git + HTML para colocar a página ao vivo na internet de graça, com URL pública para compartilhar. 🌐

Seção 01

O que é o
HTML?

Antes de escrever uma linha de CSS ou JavaScript, todo site começa com HTML. É a linguagem que dá estrutura e significado ao conteúdo — sem ela, o navegador não sabe o que é um título, um parágrafo ou uma imagem.

🏗️ Analogia

Pense em uma casa em construção. O HTML é a estrutura: as paredes, o telhado, as janelas e as portas — tudo no lugar certo, mas ainda sem pintura nem decoração. O CSS chega depois e pinta as paredes, escolhe os móveis. O JavaScript abre e fecha as janelas automaticamente.

Sem o HTML, não há onde o CSS e o JavaScript possam trabalhar. É por isso que todo projeto web começa com o arquivo index.html.

HTML significa HyperText Markup Language — Linguagem de Marcação de Hipertexto. "Marcação" porque você usa tags (marcações) para envolver o conteúdo e dizer ao navegador o que cada coisa representa.

O trio da web

Todo site moderno é construído com três linguagens que trabalham juntas. O HTML é sempre o ponto de partida — as outras dependem dele para existir na página.

Linguagem Papel Analogia Arquivo
HTML Estrutura e conteúdo 🧱 Paredes e telhado index.html
CSS Estilo e aparência 🎨 Tinta e decoração style.css
JavaScript Comportamento e interação ⚡ Eletricidade e automação script.js
💡 Repare que na página do Pearl Jam, o index.html linka os três arquivos: <link rel="stylesheet" href="style.css" /> e <script src="script.js" defer></script>. O HTML é o centro que conecta tudo.
Lembre-se

HTML não é uma linguagem de programação — é uma linguagem de marcação. Ela não executa lógica nem cálculos; ela descreve o conteúdo usando tags.

O arquivo index.html tem esse nome especial porque os servidores web (e o GitHub Pages) procuram por ele automaticamente quando alguém acessa uma pasta — é a porta de entrada do site.

Seção 02

A história do
HTML

De um documento científico criado em 1991 a uma plataforma global que suporta bilhões de sites — a evolução do HTML acompanha a própria história da internet.

1991
Tim Berners-Lee cria o HTML

Trabalhando no CERN (laboratório de física na Suíça), Tim Berners-Lee propõe o HTML como forma de compartilhar documentos científicos entre pesquisadores. A primeira versão tinha apenas 18 tags.

1995
HTML 2.0 — Primeiro padrão oficial

A IETF (Internet Engineering Task Force) publica o HTML 2.0 como padrão. Surgem formulários, tabelas e a possibilidade de incluir imagens com a tag <img>.

1997
HTML 3.2 e 4.0 — Web começa a crescer

O W3C (World Wide Web Consortium) assume o desenvolvimento. O HTML 4.0 traz suporte a CSS, scripts e acessibilidade. A web explode comercialmente.

2000
XHTML — Tentativa de rigor

O W3C tenta reformular o HTML com regras mais rígidas (XHTML). Não foi muito bem-sucedido — tags mal fechadas quebravam tudo. Os desenvolvedores odiaram.

2008
HTML5 começa a ser desenvolvido

Apple, Mozilla e Opera formam o WHATWG e começam a trabalhar no HTML5, focado em web apps, multimídia nativa e semântica. Uma revolução começa.

2014
HTML5 — Padrão oficial 🎉

O W3C publica o HTML5 como recomendação oficial. Tags semânticas como <header>, <nav>, <section>, <footer> e suporte a <video> e <audio> chegam nativamente. É o HTML que usamos hoje.

Hoje
HTML Living Standard — Em evolução constante

O WHATWG mantém o HTML como um "padrão vivo" — sem versões fixas, sempre evoluindo. Você sempre escreve <!DOCTYPE html> sem número de versão.

🌍 Tim Berners-Lee criou o HTML, o HTTP e a primeira URL — as três fundações da World Wide Web. Ele nunca patenteou nenhuma dessas invenções, deixando a web livre e aberta para todos.
Seção 03

Estrutura de um
documento HTML

Todo arquivo HTML válido precisa de um esqueleto mínimo. Esse é o ponto de partida de qualquer projeto — inclusive a página do Pearl Jam começa exatamente assim.

index.html — Estrutura mínima 
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Pearl Jam — Ten Club Tribute</title>
    <link rel="stylesheet" href="style.css" />
    <script src="script.js" defer></script>
  </head>
  <body>

    <!-- Todo o conteúdo visível vem aqui -->

  </body>
</html>
01
<!DOCTYPE html> — Declaração do tipo
Não é uma tag HTML de verdade — é uma instrução para o navegador. Diz: "este arquivo usa HTML5". Sem ela, navegadores antigos entram em modo de compatibilidade e a página pode se comportar de formas estranhas. Sempre a primeira linha de qualquer arquivo.
02
<html lang="pt-BR"> — Raiz do documento
Envolve todo o conteúdo HTML. O atributo lang informa o idioma da página — importante para leitores de tela (acessibilidade) e para o Google entender em qual idioma o site está.
03
<head> — Cabeçalho invisível
Contém metadados — informações sobre a página que o navegador lê, mas que não aparecem diretamente na tela. É aqui que ficam o título da aba, o link para o CSS, scripts, fontes e configurações de SEO.
🔤
<meta charset="UTF-8">
Define a codificação de caracteres. UTF-8 suporta acentos, emojis e praticamente todos os idiomas do mundo. Sem isso, "música" vira "m�sica".
📱
<meta name="viewport">
Controla como a página se comporta em telas de celular. O valor width=device-width garante que o site não fique minúsculo em smartphones.
🏷️
<title>
O texto que aparece na aba do navegador e nos resultados do Google. No Pearl Jam: Pearl Jam — Ten Club Tribute.
🎨
<link rel="stylesheet">
Conecta o arquivo CSS ao HTML. O atributo href aponta para o arquivo: href="style.css".
04
<body> — O corpo visível
Tudo o que aparece na tela — textos, imagens, botões, menus, seções — fica dentro do <body>. É aqui onde toda a estrutura da página do Pearl Jam é construída: o <nav>, as <section>s, o <footer>.
Anatomia de uma tag HTML
<a href="#shows">Shows</a>
Tag de abertura Atributo Valor Conteúdo Tag de fechamento
⚠️ Tags de abertura e fechamento formam um par. Esquecer o </> de fechamento é um dos erros mais comuns — e pode quebrar toda a estrutura da página abaixo daquele ponto.
Seção 04

As tags do
índex.html

Toda tag usada na página do Pearl Jam tem uma razão de ser. Vamos destrinchar cada uma, entender seu significado e ver onde ela aparece no projeto.

🏗️ Estrutura e Semântica
Tag Nome Para que serve No Pearl Jam
<nav> Navigation Área de navegação principal do site Barra com logo + links + hamburguer
<section> Section Bloco temático de conteúdo, com sentido próprio #hero, #shows, #members, #discography
<div> Division Container genérico sem significado semântico, usado para estilização hero-rings, container, stats-grid
<footer> Footer Rodapé da página com informações finais e links Links de navegação, crédito e redes sociais
💡 Tags semânticas como <nav>, <section> e <footer> comunicam o significado do bloco, não só a aparência. O Google e os leitores de tela para deficientes visuais entendem melhor a página assim do que se tudo fosse apenas <div>.
📝 Texto e Headings
Tag Nome Para que serve No Pearl Jam
<h1> Heading 1 Título principal da página — deve existir apenas um por página Pearl Jam — o grande título do hero
<h2> Heading 2 Títulos de seções principais Shows Inesquecíveis, Os Álbuns, Os Integrantes
<h3> Heading 3 Subtítulos dentro de seções Títulos dos slides de shows e dos álbuns
<p> Paragraph Parágrafo de texto Descrições de shows, bios dos membros, subtítulos
<span> Span Container inline para estilizar partes de texto <span class="highlight">Jam</span> no título
<strong> Strong Texto com ênfase forte (negrito semântico) Destaque em biografias dos integrantes
<em> Emphasis Texto com ênfase (itálico semântico) Itálico em textos descritivos
🔗 Links e Navegação
Links no Pearl Jam 
<!-- Link interno — âncora para seção da página -->
<a href="#discography" class="btn btn-primary">
  ▶ Explorar Discografia
</a>

<!-- Link externo — abre em nova aba -->
<a
  href="https://pearljam.com"
  target="_blank"
  rel="noopener"
  class="btn btn-secondary"
>Site Oficial ↗</a>

<!-- Link de navegação no nav -->
<a href="#shows">Shows</a>
Atributo do <a> Para que serve
href="#shows" Âncora interna — rola a página até o elemento com id="shows"
href="https://..." Link externo para outro site
target="_blank" Abre o link em uma nova aba do navegador
rel="noopener" Segurança: impede que a nova aba acesse a página original via JavaScript
class="btn-primary" Atribui classes CSS para estilizar o link como botão
🖼️ Imagens
Imagens no Pearl Jam 
<!-- Imagem do álbum Ten -->
<img
  src="./img/ten.png"
  alt="Pearl Jam Ten Album Cover"
  class="album-image"
/>

<!-- Imagem do Eddie Vedder -->
<img src="./img/eddie.png" alt="Eddie Vedder" />
src
Caminho da imagem
Pode ser relativo (./img/ten.png) apontando para um arquivo local, ou absoluto (https://...) para imagens na internet.
alt
Texto alternativo
Aparece quando a imagem não carrega e é lido por leitores de tela. Fundamental para acessibilidade e SEO. Nunca deixe vazio.
📋 Listas
Listas no Pearl Jam — Nav e Footer 
<!-- Lista de links no nav -->
<ul class="nav-links">
  <li><a href="#shows">Shows</a></li>
  <li><a href="#members">Integrantes</a></li>
  <li><a href="#discography">Discografia</a></li>
</ul>

<!-- Lista de links no footer -->
<ul class="footer-links">
  <li><a href="#shows">Shows</a></li>
  <li><a href="#members">Integrantes</a></li>
</ul>
Tag Nome Para que serve
<ul> Unordered List Lista sem ordem (com bolinhas por padrão, removidas com CSS)
<ol> Ordered List Lista numerada (1, 2, 3...)
<li> List Item Cada item da lista — filho direto de <ul> ou <ol>
✏️ SVG — Gráficos vetoriais
O stickman do Pearl Jam 
<!-- SVG inline: logo stickman do Pearl Jam -->
<svg
  class="stickman"
  viewBox="0 0 100 120"
  fill="none"
  xmlns="http://www.w3.org/2000/svg"
>
  <circle cx="50" cy="18" r="12" stroke="#c8722a" stroke-width="3" />
  <line x1="50" y1="30" x2="50" y2="75" stroke="#c8722a" stroke-width="3" />
  <!-- ... braços e pernas -->
</svg>
🎨 SVG (Scalable Vector Graphics) é desenhado com código diretamente no HTML. As formas mais usadas no Pearl Jam são <circle> (cabeça do stickman) e <line> (corpo, braços e pernas). SVGs são vetoriais — ficam nítidos em qualquer resolução.
💬 Comentários e Atributos importantes
Comentários e atributos no Pearl Jam 
<!-- ─── NAV ─── Comentário: não aparece na tela -->
<nav id="navbar">

  <!-- id: identifica um elemento único → usado em âncoras e JavaScript -->
  <section id="hero">

  <!-- class: grupo de elementos com o mesmo estilo -->
  <div class="hero-rings">

  <!-- onclick: executa JavaScript ao clicar -->
  <div class="hamburger" id="hamburger" onclick="toggleMenu()">

  <!-- style: CSS inline diretamente na tag -->
  <div style="background-image: url('./img/1992.png')">
Atributo Descrição Exemplo no Pearl Jam
id Identificador único — cada página pode ter apenas um elemento com aquele id id="hero", id="navbar"
class Classe CSS — muitos elementos podem ter a mesma classe class="album-card reveal"
onclick Chama uma função JavaScript quando o elemento é clicado onclick="toggleMenu()"
style CSS inline — estilos aplicados direto na tag Background das imagens dos slides
defer Carrega o script após o HTML ser interpretado — evita erros <script src="script.js" defer>
Seção 05

Construindo o
index.html

Agora que você conhece as tags, vamos ver como elas se encaixam para montar o site do Pearl Jam, seção por seção, de cima para baixo.

Mapa do index.html
<nav>
Barra de Navegação
Logo à esquerda, lista de links ao centro, botão hamburguer para mobile. O id="navbar" permite que o JavaScript adicione classe de scroll.
<section id="hero">
Seção Hero
Primeira impressão do site. Contém o SVG do stickman, o título <h1>, subtítulo <p> e dois botões <a> estilizados como botões.
<section id="stats">
Estatísticas
Grid com 4 <div class="stat-item">, cada um com um número em <span class="stat-number"> e um rótulo em <span class="stat-label">.
<section id="shows">
Carrossel de Shows
Cada slide é um <div class="carousel-slide"> com um <div class="slide-bg"> com background-image inline e conteúdo textual.
<section id="members">
Integrantes — Accordion
Cada membro é um <div class="accordion-item"> com header clicável (onclick="toggleAccordion()") e body com bio, stats e <img>.
<section id="discography">
Discografia — Cards
Grid de <div class="album-card">. Cada card tem <img> do álbum, <p> do ano, <h3> do título e <span> com o badge.
Passo a passo: montando o Nav
index.html — Navegação 
<nav id="navbar">

  <!-- Logo: um link que volta ao hero -->
  <a href="#hero" class="nav-logo">
    Pearl<span>Jam</span>
  </a>

  <!-- Lista de navegação -->
  <ul class="nav-links" id="navLinks">
    <li><a href="#shows">Shows</a></li>
    <li><a href="#members">Integrantes</a></li>
    <li><a href="#discography">Discografia</a></li>
    <li>
      <a href="https://pearljam.com"
         target="_blank"
         rel="noopener"
         class="nav-cta">Site Oficial ↗</a>
    </li>
  </ul>

  <!-- Hamburguer para mobile -->
  <div class="hamburger" id="hamburger" onclick="toggleMenu()">
    <span></span><span></span><span></span>
  </div>

</nav>

🎸 A classe reveal no card não faz nada no HTML — ela é um gancho para o JavaScript. O script.js usa o IntersectionObserver para detectar quando o card entra na tela e adiciona a classe visible, que dispara a animação definida no CSS.
📚 Glossário rápido
Tag
Marcação HTML entre < e >. Ex: <p>
Elemento
Tag de abertura + conteúdo + tag de fechamento: <p>texto</p>
Atributo
Informação extra dentro da tag: href, src, class, id
Valor
Conteúdo do atributo entre aspas: href="#shows"
Aninhamento
Tags dentro de tags. <ul><li>item</li></ul>
Âncora
Link que rola até um id: href="#hero"
Tag vazia
Tag sem conteúdo nem fechamento. Ex: <img />, <br />
Semântica
Tags com significado próprio: <nav>, <footer>, <section>
Seção 06

Publicando com
GitHub Pages

Agora que o HTML está pronto, vamos unir o que aprendemos na Aula 01 (Git + GitHub) com a Aula 02 (HTML) para publicar a página do Pearl Jam online — de graça, com URL pública.

01
Crie o repositório no GitHub
Acesse github.com e crie um repositório público chamado pearl-jam-tribute. Marque a opção "Add a README file" para inicializar com um commit.
02
Clone o repositório e adicione os arquivos
Clone o repo para sua máquina e coloque os arquivos index.html, style.css, script.js e a pasta img/ na raiz do projeto.
Terminal 
$ git clone https://github.com/seu-usuario/pearl-jam-tribute.git
$ cd pearl-jam-tribute
# Copie index.html, style.css, script.js e a pasta img/ para cá
03
Commit e push para o GitHub
Adicione todos os arquivos ao Git, crie um commit com mensagem descritiva e envie para o GitHub.
Terminal 
$ git add .
$ git commit -m "feat: página tributo Pearl Jam"
$ git push origin main
04
Ative o GitHub Pages
No repositório, vá em Settings → Pages. Em "Source", selecione a branch main e a pasta / (root). Clique em Save.
🚀 Em alguns segundos o GitHub Pages gera uma URL no formato https://seu-usuario.github.io/pearl-jam-tribute/. Compartilhe com a turma!

🎸 Desafio da Aula

Publique sua versão da página do Pearl Jam no GitHub Pages e compartilhe a URL no grupo da turma. Personalize ao menos uma seção: adicione um álbum novo, altere uma bio ou mude algum texto. O importante é que o código seja seu!
