Seção 01

O que é
HTML?

Toda página que você acessa na internet — o Instagram, o YouTube, a Netflix — começa com HTML. É ele quem diz ao navegador o que exibir na tela: títulos, textos, imagens, botões e links. Sem HTML, não existe web.

O que significa HTML?

HTML significa HyperText Markup Language — em português, Linguagem de Marcação de Hipertexto. É a linguagem responsável por estruturar o conteúdo das páginas web. Pense nela como o esqueleto de um site: sem HTML, não há títulos, textos, imagens nem links.

📌 O HTML é chamado de linguagem de marcação porque usamos marcações chamadas tags para identificar cada parte da página, como títulos, textos, imagens e links.
🏠 Analogia

Se um site fosse uma casa, o HTML seria a estrutura — paredes, portas, janelas e cômodos. O CSS seria a pintura e decoração. O JavaScript seria a automação elétrica e a campainha.

Você pode ter uma casa sem pintura, mas não pode ter uma casa sem paredes. Da mesma forma, todo site precisa de HTML — os outros são complementos.

O que o HTML faz e o que ele não faz

Entender os limites do HTML é essencial para não se confundir com CSS e JavaScript. Cada tecnologia tem sua responsabilidade dentro de uma página web.

✅ HTML FAZ
→Cria títulos, subtítulos e parágrafos
→Insere imagens e links
→Organiza seções e formulários
→Define a estrutura semântica da página
→Conecta CSS e JavaScript ao documento
❌ HTML NÃO FAZ
→Estilização visual (isso é CSS)
→Animações e efeitos visuais (CSS/JS)
→Lógica e interatividade avançada (JavaScript)
→Banco de dados ou autenticação (Back-end)
→Processamento no servidor (linguagens Back-end)
💡 No projeto Pearl Jam que vamos construir, o HTML cria toda a estrutura: o <nav>, o <section id="hero">, os cards da discografia e os botões. O CSS cuida do visual e o JavaScript das interações.
Seção 02

Estrutura Base do
Documento HTML

Todo arquivo HTML começa com a mesma base. Entender cada linha dessa estrutura é o primeiro passo para escrever código que o navegador interpreta corretamente em qualquer dispositivo.

Destrinchando cada parte da estrutura

Cada linha da estrutura base tem um propósito específico. Remover qualquer uma delas pode causar problemas de renderização, acessibilidade ou SEO. Veja o que cada parte significa.

🧠 O navegador interpreta o HTML de cima para baixo.
Por isso, a organização da estrutura influencia diretamente carregamento, SEO, estilos e scripts.
01
<!DOCTYPE html>
Informa ao navegador que o documento usa HTML5. Sem ele, o navegador entra em "modo de compatibilidade" e pode interpretar a página de forma errada — especialmente em versões antigas do Internet Explorer.
doctype 
<!DOCTYPE html>
02
<html lang="pt-BR">
É o elemento raiz do documento HTML — toda a aplicação fica dentro dele, incluindo o <head> e o <body>. O atributo lang="pt-BR" define o idioma principal da página, melhorando acessibilidade para leitores de tela, SEO e tradução automática.
lang 
<html lang="pt-BR">
    <!-- aplicação -->
</lang>
03
<head>
Contém metadados e configurações da página. Nada dentro do <head> aparece diretamente para o usuário, mas tudo aqui influencia SEO, carregamento de fontes, CSS e configuração mobile.
head 
<head>
    <!-- metadados e configurações -->
</head>
04
<meta charset="UTF-8" />
Define a codificação de caracteres. Sem UTF-8, acentos e caracteres especiais são exibidos incorretamente. João pode virar JoÃ£o se esse meta estiver ausente.
charset 
<meta charset="UTF-8" />
05
Viewport Responsiva
Sem esse meta, o site fica minúsculo no celular. Ele garante que a página se adapte corretamente ao tamanho da tela, sem zoom automático estranho ou layout quebrado.
viewport 
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
06
<title> — Título da Aba
Define o texto exibido na aba do navegador, nos favoritos e nos resultados do Google. É um dos elementos mais importantes para SEO.
title 
<title>Pearl Jam — Ten Club Tribute</title>
07
Linkando CSS e Importando Fontes
O <link> conecta o arquivo CSS ao HTML. Com o atributo rel="stylesheet" e href apontando para o arquivo. Google Fonts também é importado via <link>.
link — css e fontes 
<!-- CSS próprio -->
<link rel="stylesheet" href="style.css" />

<!-- Fonte do Google Fonts -->
<link
  href="https://fonts.googleapis.com/css2?family=Bebas+Neue&display=swap"
  rel="stylesheet"
/>
08
Script JavaScript com defer
O <script> importa o JavaScript. O atributo defer garante que o script só execute após o HTML ser lido completamente, evitando erros de elementos não encontrados.

Antigamente, era comum colocar o <script> no final do <body> para evitar problemas de carregamento. Hoje, o uso de defer dentro do <head> é uma das abordagens mais utilizadas.
script defer 
<script src="script.js" defer></script>

Estrutura completa do Pearl Jam

Agora que você já entende a função de cada parte da estrutura, veja como tudo isso se organiza em um documento HTML completo. Essa será a base inicial do projeto Pearl Jam que vamos construir.

index.html — estrutura base completa 
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Pearl Jam — Ten Club Tribute</title>
    <link rel="stylesheet" href="style.css" />
    <script src="script.js" defer></script>
  </head>
  <body>
    <!-- Conteúdo da página vai aqui -->
  </body>
</html>
📦 Resumindo

Todo documento HTML segue uma estrutura base. O navegador precisa dessa organização para interpretar corretamente o conteúdo da página.

Depois dessa estrutura pronta, começamos a construir o conteúdo visual dentro da tag <body>.

Seção 03

A Tag
<body>

Tudo que o usuário vê na tela vive dentro do <body>. Textos, imagens, botões, menus, cards, vídeos e seções fazem parte dessa área. É dentro dela que construímos toda a interface visual de uma página web.

O que existe dentro do <body>?

O <body> funciona como a área visível da página. Tudo que aparece para o usuário no navegador precisa estar dentro dessa tag: títulos, textos, imagens, menus, botões, cards, formulários e seções do site.

📝
Textos e Títulos
Todo conteúdo textual — <h1>, <h2>, <p> — fica no body e é renderizado diretamente na tela.
🖼️
Imagens e Mídia
Tags como <img>, <video> e <audio> inserem conteúdo multimídia visível ao usuário.
🔗
Links e Botões
Elementos de interação como <a> e <button> ficam no body para que o usuário clique e navegue.
🧩
Seções e Layouts
Toda estrutura visual — <nav>, <section>, <footer>, <div> — organiza o conteúdo dentro do body.

Exemplos reais dentro do <body>

Tudo que vimos nos cards agora aparece funcionando em um exemplo real. Observe como títulos, imagens, links e seções ficam organizados diretamente dentro da tag <body>.

body 
<body>
  <h1>Pearl Jam</h1>    
  <p>
    Banda de rock formada em Seattle.
  </p>
  <img
    src="show.jpg"
    alt="Show do Pearl Jam"
  />
  <a
    href="#discografia">
    Ver Discografia
  </a>
</body>
👀 Perceba que todos os elementos visíveis estão dentro do <body>.
Se um conteúdo estiver fora dele, o navegador pode ignorar ou interpretar incorretamente a estrutura da página.
⚠️ Lembre-se:
O <head> contém configurações invisíveis ao usuário.
O <body> contém tudo que aparece na tela.
Colocar um <link> de CSS dentro do body tecnicamente funciona, mas é considerado uma má prática.

Como o navegador lê o HTML?

O navegador interpreta o HTML seguindo uma ordem lógica. A leitura acontece de cima para baixo e, dentro de cada linha, da esquerda para a direita.

Isso significa que os elementos são carregados conforme aparecem no documento. Primeiro o navegador lê o que está no topo do arquivo, depois continua descendo até o final da página.

⬇️
Fluxo Vertical
O HTML é interpretado de cima para baixo. Um elemento escrito primeiro normalmente será carregado e exibido antes dos próximos elementos.
➡️
Fluxo Horizontal
Dentro de cada linha, a leitura acontece da esquerda para a direita, seguindo o padrão natural de leitura da maior parte das interfaces web.
🧱
Ordem Importa
A posição dos elementos influencia diretamente a organização visual e a estrutura lógica da página.
🎯
Renderização
Conforme o navegador lê o HTML, ele monta a interface visual do site na tela do usuário.

Observe o exemplo abaixo. O navegador começa lendo o <h1>, depois o parágrafo <p> e, por último, a imagem <img>.

fluxo-de-leitura 
<body>

  <h1>Título Principal</h1>

  <p>
    Este texto será lido após o título.
  </p>

  <img
    src="foto.jpg"
    alt="Imagem de exemplo"
  />

</body>
🧠 Pense no HTML como uma fila de instruções. O navegador vai lendo cada elemento em sequência para montar a estrutura visual da página.
Seção 04

Atributos de Controle
e Agrupamento

HTML sozinho define apenas a estrutura da página. Mas como o CSS sabe qual elemento estilizar? E como o JavaScript sabe qual elemento manipular? É aqui que entram os atributos id e class, além das tags de agrupamento <div> e <span> — os verdadeiros “controles remotos” da interface.

Os atributos id e class

Esses atributos funcionam como nomes e identificadores dos elementos HTML. Eles criam “ganchos” para o CSS aplicar estilos e para o JavaScript localizar elementos na página.

🆔 id
→ Identificador único da página
→ Não deve se repetir
→ Usado para âncoras, JavaScript e seções específicas
→ CSS seleciona usando #nome
🏷️ class
→ Pode ser reutilizada em vários elementos
→ Ideal para estilos repetidos
→ Permite criar componentes visuais reutilizáveis
→ CSS seleciona usando .nome
id e class 
<!-- id: único na página -->
<section id="discografia">

  <!-- class: reutilizável -->
  <div class="album-card">
    <h3>Ten</h3>
  </div>

  <div class="album-card">
    <h3>VS</h3>
  </div>

</section>

As caixas <div> e <span>

Essas tags não possuem significado semântico próprio. Elas existem para agrupar elementos e criar pontos de controle para CSS e JavaScript.

📦 <div>
→ Elemento de bloco
→ Ocupa toda a largura disponível
→ Usado para estruturar layouts e seções
✏️ <span>
→ Elemento inline
→ Não quebra linha
→ Usado para estilizar partes específicas do texto
div e span 
<div class="card">

  <h3>
    Pearl <span class="highlight">Jam</span>
  </h3>

  <p>
    Banda formada em Seattle em 1990.
  </p>

</div>
🎮 Analogia prática

Pense no HTML como uma casa:

O id funciona como o número único da residência. Já a class funciona como categorias: “quartos”, “janelas”, “portas”.

A <div> é uma caixa grande usada para organizar ambientes. O <span> é como um marcador pequeno dentro de um texto.

Sem id e class, CSS e JavaScript ficariam “cegos”, sem saber em qual elemento agir.

⚠️ Evite criar nomes genéricos como class="div1" ou class="teste". Prefira nomes descritivos como album-card, hero-title ou footer-links.
Seção 05

Tipografia e
Hierarquia

O conteúdo de uma página é comunicado através de texto. HTML oferece um conjunto de tags que não apenas formata o texto, mas define sua importância, ênfase e estrutura lógica — dando voz e ordem ao que o usuário lê.

Tags de Títulos — <h1> a <h6>

O HTML oferece seis níveis de título. O <h1> é o mais importante da página — deve existir apenas um por página e descrever o tema principal. Os demais criam uma hierarquia de subtítulos, como capítulos e seções de um livro.

⚠️ Não pule níveis de heading por questões visuais. Se precisar de um texto menor, use CSS. Pular de <h1> para <h4> prejudica acessibilidade e SEO.
headings — h1 a h6 
<h1>Pearl Jam — Ten Club Tribute</h1>   <!-- título principal da página -->
<h2>Discografia</h2>                     <!-- seção de nível 2 -->
<h3>Álbuns dos anos 90</h3>               <!-- subseção de nível 3 -->
<h4>Ten (1991)</h4>                       <!-- agrupamento menor -->
<h5>Faixas principais</h5>
<h6>Curiosidades</h6>

Parágrafos e Texto Inline

O <p> cria blocos de texto (elementos de bloco). Já <strong>, <em> e <span> são elementos inline — funcionam dentro de um parágrafo sem quebrá-lo, adicionando ênfase ou marcação semântica.

📋 Tag
→<p> — parágrafo de texto
→<strong> — importância semântica (negrito)
→<em> — ênfase sutil (itálico)
→<span> — marcação sem semântica própria
→<br> — quebra de linha
→<hr> — linha divisória temática
✅ Exemplo real
<p>
  O álbum <strong>Ten</strong> foi lançado
  em <em>27 de agosto de 1991</em>
  e é considerado um dos maiores
  discos do grunge.
  Vendeu mais de
  <span class="destaque">
    13 milhões de cópias
  </span>
  nos Estados Unidos.
</p>

Listas: <ul>, <ol> e <li>

Listas organizam itens relacionados. A diferença fundamental: <ul> é para itens sem ordem específica (como ingredientes), enquanto <ol> é para itens com ordem importa (como passos de instalação). Todo item de lista usa <li>.

ul, ol e li 
<!-- Lista não ordenada: membros da banda -->
<ul>
  <li>Eddie Vedder — vocal</li>
  <li>Mike McCready — guitarra</li>
  <li>Stone Gossard — guitarra</li>
  <li>Jeff Ament — baixo</li>
</ul>

<!-- Lista ordenada: passo a passo -->
<ol>
  <li>Clone o repositório</li>
  <li>Crie o arquivo index.html</li>
  <li>Publique no GitHub Pages</li>
</ol>
🗂️ Regra de ouro

Use <strong> quando o conteúdo tiver importância semântica real (como um alerta ou nome de produto). Use CSS font-weight: bold quando for apenas estilo visual. O mesmo vale para <em> vs CSS font-style: italic.

<span> é o "canivete suíço" inline — sem semântica própria, serve apenas para aplicar classes CSS ou selecionar partes do texto com JavaScript.

Tabela de consulta rápida

Essas são algumas das principais tags utilizadas para estruturar conteúdo textual em HTML. Cada uma possui uma função específica relacionada à semântica, organização e apresentação do conteúdo da página.

Tag Função Exemplo
<h1> até <h6> Criam títulos e subtítulos hierárquicos. <h1> representa o título principal e <h6> o menor nível de importância. <h1>Título Principal</h1>
<p> Define um parágrafo de texto. É a principal tag para conteúdos textuais. <p>Meu parágrafo.</p>
<strong> Indica forte importância semântica. Normalmente exibido em negrito. <strong>Importante</strong>
<em> Dá ênfase semântica ao texto. Geralmente exibido em itálico. <em>Ênfase</em>
<span> Contêiner inline usado para estilizar ou manipular partes específicas do texto. <span>Texto</span>
<br> Insere uma quebra de linha dentro do conteúdo. Linha 1<br>Linha 2
<hr> Cria uma linha horizontal para separação temática de conteúdo. <hr>
<ul> Cria uma lista não ordenada (com marcadores). <ul>...</ul>
<ol> Cria uma lista ordenada (numerada). <ol>...</ol>
<li> Representa um item dentro de listas <ul> ou <ol>. <li>Item</li>
💡 A hierarquia textual é fundamental para a organização visual e semântica da página. Use <h1> até <h6> em ordem lógica, mantendo apenas um <h1> principal por página sempre que possível. Isso melhora a leitura, a acessibilidade e o entendimento do conteúdo pelos buscadores.
Seção 06

Links e
Navegação

A tag <a> (âncora) é o que torna a web uma teia de conexões. Com ela conectamos páginas, seções, arquivos e endereços externos — criando a navegação que o usuário percorre ao explorar um site.

A tag <a> e seus atributos

O elemento âncora tem um atributo essencial — o href (Hypertext REFerence) — que define o destino do link. Mas existem outros atributos que controlam o comportamento da navegação e a segurança do link.

Atributo Valor(es) comuns Função
href "https://...", "#id", "pagina.html" Define o destino do link — obrigatório para navegação funcionar
target "_blank", "_self" _blank abre em nova aba; _self abre na mesma aba (padrão)
rel "noopener", "noreferrer" Segurança: evita que a nova aba acesse a janela original via JavaScript
download "arquivo.pdf" Força o download do arquivo ao invés de abri-lo
title "Descrição do link" Tooltip exibido ao passar o mouse; útil para acessibilidade

Tipos de links

01
Link Externo
Aponta para outra URL na internet. Sempre use target="_blank" com rel="noopener noreferrer" por segurança — sem isso, a nova aba pode manipular a página original.
link externo 
<a
  href="https://pearljam.com"
  target="_blank"
  rel="noopener noreferrer"
>
  Site oficial do Pearl Jam
</a>
02
Âncora Interna
O href com #id leva o usuário para uma seção específica da mesma página — útil em menus de navegação como o do nosso projeto Pearl Jam.
âncora interna 
<!-- Link no menu -->
<a href="#discografia">Discografia</a>

<!-- Seção de destino (mais abaixo na página) -->
<section id="discografia">
  <h2>Discografia</h2>
</section>
03
Links Especiais
O href aceita protocolos especiais: mailto: para abrir o cliente de e-mail, tel: para discagem no celular, e caminhos relativos para arquivos locais do projeto.
links especiais 
<!-- Abre cliente de e-mail -->
<a href="mailto:contato@pearljam.com">Enviar e-mail</a>

<!-- Discagem direta no celular -->
<a href="tel:+5548999990000">Ligar agora</a>

<!-- Download de arquivo -->
<a href="setlist.pdf" download>Baixar Setlist</a>
💡 Um link com href="#" não leva a lugar nenhum — rola a página para o topo. Para links sem destino definido ainda, prefira href="javascript:void(0)" ou use um <button> com CSS, que é semanticamente mais correto para ações.
Seção 07

Estrutura
Semântica

HTML semântico significa usar a tag certa para o conteúdo certo. Não é apenas estética de código: é acessibilidade, SEO, organização e manutenção profissional.

O que é HTML semântico?

Antes do HTML5, desenvolvedores usavam <div> para praticamente tudo. O HTML5 trouxe tags com significado — como <nav>, <section>, <article> e <footer> — que descrevem a função de cada parte da página, não apenas sua aparência.

📰 Analogia — Jornal

Imagine um jornal impresso: ele tem um cabeçalho, seções temáticas, artigos individuais e um rodapé. O HTML semântico funciona exatamente assim — cada tag descreve o papel daquela parte, tornando a página compreensível para humanos, buscadores e leitores de tela.

Por que usar?

O impacto vai além da organização do código. HTML semântico beneficia três áreas fundamentais:

SEO
Melhor indexação
Mecanismos de busca como o Google entendem a hierarquia do conteúdo com mais precisão, o que pode melhorar o posicionamento nos resultados de pesquisa.
Acessibilidade
Leitores de tela
Tecnologias assistivas usam as tags para anunciar regiões da página. Um <nav> é anunciado como "navegação"; um <div> não diz nada.
Manutenção
Código legível
Qualquer desenvolvedor que abrir o código entende a estrutura imediatamente, sem precisar decifrar camadas de <div>s aninhados.

Semântico vs não semântico

Ambos os exemplos abaixo funcionam visualmente, mas apenas um descreve corretamente o significado do conteúdo.

❌ Não Semântico
<div>
  <div>Menu</div>    
  
  <div>
    <div>Conteúdo 01</div>
    <div>Conteúdo 02</div>       
  </div>
      
  <div>Rodapé</div>
</div>
✅ Semântico
<header>
  <nav>Menu</nav>
</header>
      
<main>
  <section>Conteúdo 01</section>
  <section>Conteúdo 02</section>
</main>
      
<footer>Rodapé</footer>

Tags semânticas mais utilizadas

Conheça as principais tags semânticas do HTML5 e quando usar cada uma delas.

Tag Função Quando usar
<header> Cabeçalho da página ou seção Logotipo, título, navegação principal
<nav> Bloco de navegação Menus principais, paginação, índices
<main> Conteúdo principal da página Único por página; envolve o conteúdo central
<section> Seção temática do conteúdo Blocos com tema próprio; sempre com um título
<article> Conteúdo independente e reutilizável Posts, notícias, cards, comentários
<aside> Conteúdo lateral ou complementar Barras laterais, dicas, links relacionados
<footer> Rodapé da página ou seção Direitos autorais, contatos, links extras
<figure> Conteúdo visual com legenda Imagens, diagramas, trechos de código ilustrativos
<figcaption> Legenda do <figure> Sempre dentro de um <figure>
<time> Data ou horário legível por máquinas Datas de publicação, eventos, agendas
🧠 Quando estiver em dúvida entre <section> e <div>, pergunte-se: "esse bloco tem um tema próprio e um título?" Se sim, use <section>. Se for apenas agrupamento visual, use <div>.
Seção 08

Imagens e
Mídia

Imagens, vídeos e áudios enriquecem o conteúdo visual de uma página. Mas além de inserir mídia, o HTML exige atenção à acessibilidade — garantindo que todos os usuários, incluindo os que usam leitores de tela, tenham uma experiência completa.

A tag <img> e o atributo alt

A tag <img> é um elemento vazio (sem tag de fechamento separada). O atributo src define o caminho da imagem e o alt fornece uma descrição textual — obrigatória para leitores de tela e exibida quando a imagem falha ao carregar.

🚫 Nunca omita o atributo alt. Para imagens decorativas sem significado semântico, use alt="" (string vazia) — isso instrui o leitor de tela a ignorá-la. Mas para imagens de conteúdo, sempre descreva o que está sendo exibido.
img — atributos essenciais 
<!-- Imagem com alt descritivo (conteúdo) -->
<img

Seção 09

Gráficos
Vetoriais — SVG

SVG (Scalable Vector Graphics) é uma linguagem de marcação para descrever gráficos vetoriais diretamente no HTML. Diferente de imagens rasterizadas (JPG, PNG), gráficos SVG nunca perdem qualidade ao ser ampliados — são matematicamente perfeitos em qualquer resolução.

Por que usar SVG?

Ícones, logotipos, ilustrações e gráficos em SVG têm tamanho de arquivo reduzido, podem ser estilizados com CSS, animados com JavaScript e são acessíveis por leitores de tela. São a escolha certa para qualquer elemento gráfico que precise ser responsivo.

📐
Escalável
Define formas com coordenadas matemáticas. Amplie para qualquer tamanho sem perda de qualidade — ideal para telas retina e 4K.
🎨
Estilizável com CSS
Atributos como fill, stroke e opacity podem ser sobrescritos por CSS, permitindo temas dinâmicos como dark/light mode.
⚡
Leve e performático
Um ícone SVG simples pode ter menos de 1KB. PNG equivalente pode ter 20KB. Em páginas com muitos ícones, a diferença é significativa.
♿
Acessível
Com <title> e aria-label dentro do SVG, leitores de tela conseguem interpretar e anunciar o conteúdo gráfico.

Tags e atributos essenciais

01
<svg> — o contêiner
Todo SVG começa aqui. O viewBox define o sistema de coordenadas interno; width e height definem o tamanho no layout. Definir apenas viewBox e controlar o tamanho via CSS é a abordagem mais responsiva.
svg container 
<svg
  viewBox="0 0 100 100"
  xmlns="http://www.w3.org/2000/svg"
  width="200"
  height="200"
>
  <!-- formas aqui -->
</svg>
02
Formas básicas: <circle>, <rect>, <line>
As formas primitivas do SVG. Coordenadas referem-se ao sistema interno do viewBox.
circle, rect, line 
<!-- Círculo: cx, cy = centro; r = raio -->
<circle cx="50" cy="50" r="40" fill="#e44d26" />

<!-- Retângulo: x, y = canto superior-esquerdo -->
<rect x="10" y="10" width="80" height="80" rx="8" fill="none" stroke="#38bdf8" stroke-width="2" />

<!-- Linha: coordenadas de início e fim -->
<line x1="0" y1="0" x2="100" y2="100" stroke="#facc15" stroke-width="2" />
03
<polygon> e <path>
<polygon> conecta uma lista de pontos formando um polígono fechado. <path> é o mais poderoso — permite desenhar qualquer forma com comandos como M (mover), L (linha), C (curva bezier) e Z (fechar).
polygon e path 
<!-- Triângulo com polygon -->
<polygon
  points="50,10 90,90 10,90"
  fill="rgba(228,77,38,0.3)"
  stroke="#e44d26"
  stroke-width="2"
/>

<!-- Curva com path -->
<!-- M = move to | Q = quadratic bezier | Z = close -->
<path
  d="M 10,50 Q 50,10 90,50 Z"
  fill="none"
  stroke="#38bdf8"
  stroke-width="2"
/>

🎯 SVG inline vs arquivo externo

SVG pode ser usado de duas formas: inline (colado diretamente no HTML, dentro de <svg></svg>) ou como arquivo externo via <img src="icone.svg">.

Seção 10

Tabelas de
Dados

Tabelas HTML existem para representar dados tabulares — informações que possuem relação entre linhas e colunas. Quando estruturadas corretamente, tornam conteúdos complexos mais legíveis, acessíveis e semanticamente compreensíveis.

O que é uma tabela HTML?

Uma tabela HTML organiza informações em uma estrutura de linhas e colunas. Cada dado ganha significado pelo cruzamento entre:

  • a linha à qual pertence;
  • a coluna em que está localizado;
  • e o cabeçalho que o descreve.

Pense em uma tabela como uma planilha: o usuário consegue comparar informações horizontalmente e verticalmente com rapidez. Isso torna tabelas ideais para relatórios, rankings, estatísticas, agendas, catálogos e dados financeiros.

Quando uma tabela faz sentido?

O uso correto de tabelas depende do tipo de informação. Nem tudo organizado em “quadrados” deve ser uma tabela.

Uso correto
Dados comparáveis
Tabelas funcionam bem quando o usuário precisa comparar informações entre linhas e colunas: preços, notas, relatórios, rankings, vendas, horários, planilhas e estatísticas.
Uso incorreto
Layout visual
Menus, sidebars, grids de cards e estrutura de páginas NÃO são dados tabulares. Para layout visual moderno, utilize Flexbox ou CSS Grid.

Como o navegador interpreta a tabela

O navegador não enxerga a tabela como “linhas desenhadas”. Ele interpreta uma hierarquia semântica organizada. Cada elemento possui uma função específica.

hierarquia semântica da tabela 
table
 ├── thead
 │    └── tr
 │         └── th
 │
 ├── tbody
 │    └── tr
 │         └── td
 │
 └── tfoot
      └── tr
           └── td

Essa organização ajuda navegadores, mecanismos de busca, leitores de tela e ferramentas de acessibilidade a compreenderem a relação entre os dados.

Anatomia de uma tabela HTML

Uma tabela semântica é formada por elementos especializados. Cada um possui responsabilidade própria dentro da estrutura.

01
<table> — o contêiner principal
Envolve toda a tabela. É o elemento raiz da estrutura tabular. Dentro dele ficam cabeçalho, corpo e rodapé.
02
<thead> e <th> — cabeçalhos
<thead> agrupa as linhas de cabeçalho. Dentro dele, <th> representa células de título. Leitores de tela anunciam esses cabeçalhos antes dos dados correspondentes.
03
<tbody>, <tr> e <td>
<tbody> contém os dados principais. Cada linha é um <tr> (table row) e cada célula é um <td> (table data).
04
<tfoot> — rodapé da tabela
Utilizado para totais, médias, observações e resumos finais. Ele representa semanticamente o fechamento dos dados tabulares.

O papel do <caption>

O elemento <caption> define um título semântico para a tabela. Não é apenas um texto visual: leitores de tela anunciam o caption antes da leitura dos dados, ajudando usuários a entender o contexto da informação.

Contexto
Explica a tabela
O caption informa imediatamente o assunto dos dados exibidos.
Acessibilidade
Leitores de tela
Tecnologias assistivas anunciam o caption antes das células, contextualizando a navegação.
Semântica
Descrição estrutural
O navegador entende que aquele texto descreve oficialmente a tabela.

  <caption>
    Vendas de álbuns do Pearl Jam entre 1991 e 1998
  </caption>

  ...

</table>

scope="row" Cabeçalho de linha Primeira célula horizontal

</thead>

Seção 11

Formulários e
Interatividade

Formulários são a principal forma de coletar informações do usuário. Login, cadastro, busca, contato, compra — tudo passa por um <form>. Construí-los corretamente envolve semântica, acessibilidade e usabilidade juntos.

O que é um formulário?

Um formulário HTML é um contêiner que agrupa campos de entrada e permite que o usuário envie dados ao servidor. Quando o usuário clica em "Enviar", o navegador coleta os valores de todos os campos dentro do <form> e os transmite para o endereço definido no atributo action.

Pense num formulário como um envelope: o <form> é o envelope, os campos são o conteúdo, e o botão de envio é o ato de selar e postar. Sem o envelope, os dados não têm destino nem estrutura.

A estrutura de um <form>

O elemento <form> possui dois atributos fundamentais que definem o comportamento do envio:

Atributo O que define Exemplo
action URL para onde os dados serão enviados. Sem ele, o formulário envia para a própria página. action="/enviar"
method="GET" Os dados vão na URL — visíveis e compartilháveis. Ideal para buscas e filtros. /busca?q=Pearl+Jam
method="POST" Os dados vão no corpo da requisição — invisíveis na URL. Ideal para senhas e dados sensíveis. Login, cadastro, pagamento
form — estrutura base 
<form action="/enviar" method="POST">

  <label for="nome">Nome completo</label>
  <input
    type="text"
    id="nome"
    name="nome"
    placeholder="Ex: Eddie Vedder"
    required
  />

  <label for="email">E-mail</label>
  <input type="email" id="email" name="email" required />

  <label for="mensagem">Mensagem</label>
  <textarea id="mensagem" name="mensagem" rows="5"></textarea>

  <button type="submit">Enviar mensagem</button>

</form>

O papel do <label>

O <label> é a legenda de um campo. Ele informa ao usuário — e ao navegador — o significado daquele input. Mais do que texto visual, o label melhora a experiência, a acessibilidade e a interpretação semântica do formulário.

Usabilidade
Interação facilitada
Ao clicar no <label>, o campo associado recebe foco automaticamente. Em checkboxes e radios, isso amplia a área clicável e melhora a experiência do usuário.
Acessibilidade
Leitores de tela
Tecnologias assistivas anunciam o label junto ao campo. Sem ele, usuários podem ouvir apenas “campo de texto”, sem contexto sobre a informação solicitada.
Semântica
Relação entre campo e legenda
O navegador entende qual texto descreve cada input, permitindo melhor autopreenchimento, validação e interpretação da estrutura do formulário.

A associação entre label e campo é feita pelos atributos for e id: o valor de for no label deve ser idêntico ao valor de id no campo correspondente.

label — associação for/id 
<!-- "for" no label deve ser igual ao "id" no input -->

<label for="email">E-mail</label>
<input type="email" id="email" name="email" />

<!-- Em checkbox, o label amplia a área clicável -->

<input type="checkbox" id="termos" name="termos" />
<label for="termos">Aceito os termos de uso</label>
⚠️ Não use placeholder como substituto do label. O placeholder desaparece ao digitar — o usuário perde a referência do campo. Label e placeholder têm papéis distintos: o label identifica o campo, o placeholder sugere um exemplo de preenchimento.

Tipos de <input>

O atributo type define o comportamento e a validação automática do campo. Usar o tipo correto melhora a experiência no mobile (abre o teclado adequado) e ativa validação nativa do navegador sem JavaScript.

Atributos essenciais dos campos

Esses atributos aparecem em quase todos os formulários reais. Entendê-los como conceito é o que separa um formulário funcional de um formulário acessível, usável e seguro.

Controles de Interação

Além dos campos de texto, os formulários usam controles específicos para interação: caixas de seleção, botões de escolha única e botões de ação. Cada um tem semântica e comportamento próprios.

Controle Uso ideal Comportamento
checkbox Múltiplas escolhas independentes O usuário pode marcar várias opções ao mesmo tempo
radio Escolha única em um grupo Apenas uma opção pode ser selecionada por grupo de name
button type="submit" Enviar formulário Dispara o envio dos dados do <form>
button type="reset" Limpar formulário Restaura os valores iniciais dos campos
button type="button" Ações genéricas Não envia o formulário; normalmente usado com JavaScript
checkbox e radio 
<!-- Checkbox: múltiplas seleções independentes -->
<input type="checkbox" id="jazz" name="genero" value="jazz" />
<label for="jazz">Jazz</label>

<input type="checkbox" id="rock" name="genero" value="rock" checked />
<label for="rock">Rock</label>

<!-- Radio: apenas uma opção por grupo (mesmo name) -->
<input type="radio" id="sim" name="confirmacao" value="sim" />
<label for="sim">Sim</label>

<input type="radio" id="nao" name="confirmacao" value="nao" />
<label for="nao">Não</label>

Para botões de ação, o HTML oferece três variações com comportamentos distintos. Use <button> em vez de <input type="submit"> — o <button> aceita HTML interno (ícones, spans), é mais fácil de estilizar e é o padrão no desenvolvimento profissional moderno.

button — três tipos 
<!-- submit: envia o formulário -->
<button type="submit">Enviar</button>

<!-- reset: limpa todos os campos do formulário -->
<button type="reset">Limpar</button>

<!-- button: ação genérica — não envia nem limpa; controlado via JavaScript -->
<button type="button" onclick="salvarRascunho()">Salvar rascunho</button>
💡 Um <button> sem atributo type dentro de um <form> se comporta como type="submit" por padrão. Isso causa envios acidentais ao clicar em botões que deveriam apenas executar JavaScript. Sempre declare o type explicitamente.

<select> — Menu de seleção

O elemento <select> cria uma lista suspensa de opções. É ideal quando há muitas alternativas para exibir como radio buttons seria impraticável — a partir de cinco ou seis opções, um <select> mantém o formulário compacto. Seção 12

SEO e
Meta Tags

Já vimos que o <head> configura o documento. Agora vamos aprofundar o que vai dentro dele para controlar como sua página é encontrada pelo Google, exibida nas redes sociais e reconhecida por navegadores e dispositivos.

Para quem o <head> fala?

O <head> não renderiza conteúdo visual, mas funciona como a central de configuração do documento. Enquanto o <body> conversa com o usuário, o <head> conversa com navegadores, buscadores e plataformas de compartilhamento.

Nesta seção vamos nos aprofundar nas meta tags que definem identidade, SEO e presença social — os elementos que separam um site amador de um projeto profissional.

Navegador
Como renderizar a página
Charset, viewport, CSS, favicon e scripts são lidos antes de qualquer conteúdo visual ser exibido.
SEO
Como o Google entende o site
Meta tags informam título, descrição, idioma, relevância e contexto para os mecanismos de busca.
Compartilhamento
Como o link aparece nas redes
WhatsApp, Discord, LinkedIn e Twitter usam Open Graph para gerar cards com imagem, descrição e título.

<title> — O título oficial da página

O elemento <title> define o nome da página para o navegador e para os mecanismos de busca. É um dos elementos mais importantes para SEO e deve ser claro, objetivo e conter a principal palavra-chave da página.

Ele aparece em quatro lugares diferentes:

Onde aparece Como é exibido
Aba do navegador Identifica a página entre múltiplas abas abertas
Resultados do Google Primeiro texto clicável no resultado de busca
Favoritos / bookmarks Nome sugerido ao salvar a página
Histórico e compartilhamentos Identifica a página em listas e links
title — exemplos bons e ruins 
<!-- ❌ Ruim: genérico e sem contexto -->
<title>Home</title>

<!-- ❌ Ruim: keyword stuffing (excesso de palavras-chave) -->
<title>Pearl Jam Pearl Jam Banda Pearl Jam Rock Grunge Pearl Jam</title>

<!-- ✅ Bom: claro, específico e descritivo -->
<title>Pearl Jam — Discografia, História e Letras</title>
📌 O ideal é manter o <title> entre 50 e 60 caracteres. Títulos muito longos são cortados nos resultados do Google.

meta description — A descrição no Google

A meta description é o texto exibido abaixo do título nos resultados de busca. Não é um fator de ranking direto, mas influencia a taxa de clique (CTR) — uma descrição atraente convida o usuário a acessar a página. Deve ter entre 150 e 160 caracteres.

meta description e author 
<head>
  <title>Pearl Jam — Ten Club Tribute</title>

  <!-- Descrição exibida nos resultados do Google -->
  <meta
    name="description"
    content="Site tributo ao Pearl Jam com discografia completa, letras e história da banda de Seattle fundada em 1990."
  />

  <!-- Autor da página -->
  <meta name="author" content="Anderson Dutra" />

</head>

viewport — Responsividade no celular

A meta tag viewport controla como a página se adapta em dispositivos móveis. Sem ela, celulares tentam renderizar o site como uma página desktop miniaturizada — textos minúsculos, layout quebrado e zoom manual obrigatório.

viewport — responsividade 
<!-- Faz o layout acompanhar a largura real do dispositivo -->

<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0"
/>
Sem viewport
Layout quebrado no mobile
O navegador reduz toda a página para caber na tela, deixando textos minúsculos e obrigando zoom manual.
Com viewport
Layout responsivo
O CSS responsivo funciona corretamente, respeitando a largura real do dispositivo.

charset — Codificação de caracteres

O atributo charset define o conjunto de caracteres utilizado pela página. O padrão universal hoje é UTF-8, que suporta acentos, símbolos especiais e caracteres de praticamente todos os idiomas.

charset UTF-8 
<!-- Permite acentos, símbolos e caracteres especiais corretamente -->

<meta charset="UTF-8" />

robots — Controle de indexação

A meta tag robots informa aos mecanismos de busca se a página pode ser indexada e se os links devem ser seguidos. É útil para páginas privadas, áreas administrativas, ambientes de teste ou conteúdo que não deve aparecer no Google.

Valor O que faz Uso comum
index, follow Permite indexação e segue os links da página Padrão — páginas públicas normais
noindex, nofollow Bloqueia indexação e não segue links Admin, login, staging, páginas privadas
noindex, follow Não indexa a página, mas segue os links Páginas de redirecionamento ou legais

<!-- Bloqueia indexação — página não aparece no Google -->
<meta name="robots" content="noindex, nofollow" />

Open Graph — Como aparecer nas redes sociais

Quando alguém cola um link no WhatsApp, Discord ou LinkedIn, a plataforma busca as OG tags (Open Graph) para montar o card de visualização — imagem, título e descrição. Sem elas, o compartilhamento aparece genérico ou completamente sem imagem.

O favicon é o ícone exibido na aba do navegador, nos favoritos e na tela inicial do celular quando o usuário salva o site. O padrão profissional é fornecer múltiplos formatos para cobrir todos os contextos de uso.

<link rel="manifest" href="site.webmanifest" />

Deploy com
GitHub Pages

Até aqui, seu projeto existia apenas no computador. Agora vamos publicar o site na internet usando o GitHub Pages — transformando seu repositório em um site real, acessível por link em qualquer navegador.

O que é deploy?

Deploy é o processo de publicar uma aplicação na internet. Enquanto o desenvolvimento acontece localmente no seu computador, o deploy move os arquivos para um servidor acessível publicamente.

Em outras palavras: o projeto deixa de existir apenas no VS Code e passa a possuir uma URL real, que qualquer pessoa pode acessar pelo navegador.

Desenvolvimento
Projeto local
Os arquivos existem apenas no seu computador. Somente você consegue visualizar a aplicação.
Deploy
Publicação
Os arquivos são enviados para um servidor e se tornam acessíveis via internet.
Resultado
Site online
O projeto ganha uma URL pública, podendo ser compartilhado no navegador.

O que é o GitHub Pages?

O GitHub Pages é um serviço gratuito do GitHub que permite hospedar sites estáticos diretamente a partir de um repositório.

Sites estáticos são aplicações compostas apenas por:

  • HTML
  • CSS
  • JavaScript
  • Imagens e arquivos estáticos

Isso torna o GitHub Pages perfeito para:

Ideal para
Portfólios e Landing Pages
Sites institucionais, páginas pessoais, documentações e projetos front-end.
Ideal para
Projetos acadêmicos
Trabalhos, protótipos, exercícios e aplicações HTML/CSS/JS.
🧠 O GitHub Pages não executa back-end em Node.js, PHP ou Python. Ele serve arquivos estáticos — ou seja, HTML, CSS, JavaScript e assets.

Salve a configuração

⚠️ O GitHub Pages publica automaticamente o conteúdo da branch selecionada. Sempre que você fizer um novo git push, o site será atualizado novamente.

Após salvar, o GitHub exibirá uma mensagem informando que o deploy está sendo realizado. Em alguns segundos — ou poucos minutos — o endereço público do site aparecerá logo acima da configuração.

Seção 14

Boas 💡
Práticas

Escrever HTML que apenas funciona é o começo. O desenvolvimento profissional exige organização, semântica, acessibilidade, legibilidade e consistência. As práticas desta seção são o que transformam código comum em código profissional.

Qualidade de Código no HTML

Bons projetos não são definidos apenas pela aparência visual. A estrutura interna do código influencia manutenção, trabalho em equipe, SEO, acessibilidade e evolução futura do sistema.

Um HTML organizado reduz bugs, facilita estilização no CSS, melhora a leitura para outros desenvolvedores e torna o projeto mais escalável.

🧱
Use HTML Semântico
Prefira elementos como <header>, <nav>, <main>, <section> e <footer> em vez de criar tudo apenas com <div>. O HTML semântico comunica intenção.
🔖
Nomeie Classes Corretamente
Use nomes descritivos como hero-title, album-card ou menu-mobile. Bons nomes tornam o CSS mais legível e facilitam manutenção futura.
💬
Organize e Indente
Utilize indentação consistente, comentários de seção e separação lógica entre blocos. Código organizado acelera leitura, debugging e colaboração.
♿
Não Esqueça o ALT
Toda imagem relevante deve possuir atributo alt. Isso melhora acessibilidade, SEO e garante descrição visual quando a imagem não carrega.
📱
Pense em Responsividade
Estruture o HTML considerando diferentes tamanhos de tela. Um layout bem organizado facilita adaptação para mobile no CSS.
🚫
Evite Código Duplicado
Repetições excessivas dificultam manutenção. Componentes parecidos devem seguir padrões reutilizáveis de estrutura e classes.
ℹ️ Organização de Pastas: mantenha o index.html na raiz do projeto, crie uma pasta css/ para estilos, js/ para scripts e img/ para imagens. Estrutura organizada facilita crescimento do projeto.
🧠 Resumindo

HTML profissional não é apenas aparência — é clareza, semântica, acessibilidade e organização.

Quanto maior o projeto, mais importante se torna escrever código limpo. Boas práticas reduzem problemas, facilitam manutenção e tornam seu trabalho mais profissional.

📖 Glossário

Os principais termos técnicos que você irá encontrar constantemente no desenvolvimento web com HTML.

HTML
Sigla para HyperText Markup Language. É a linguagem responsável pela estrutura das páginas web, organizando títulos, textos, imagens, links e outros elementos.
Tag
Elemento utilizado para marcar e estruturar conteúdos em HTML. Normalmente possui abertura e fechamento, como <p> e </p>.
Elemento
Conjunto formado pela tag de abertura, conteúdo e tag de fechamento. Exemplo: <h1>Título</h1>.
Atributo
Informação adicional adicionada a uma tag. Exemplo: src, href, alt e class.
Semântica
Uso de tags que descrevem claramente o significado do conteúdo, como <header>, <main>, <article> e <footer>.
DOM
Sigla para Document Object Model. Representação em árvore da página HTML utilizada pelo navegador e pelo JavaScript.
Head
Área invisível da página que contém metadados, configurações, favicon, SEO, links de CSS e scripts.
Body
Parte visível da página. Tudo que aparece para o usuário no navegador fica dentro da tag <body>.
Meta Tag
Tag utilizada para fornecer informações extras sobre a página ao navegador, buscadores e redes sociais.
SEO
Sigla para Search Engine Optimization. Conjunto de práticas para melhorar o posicionamento da página em buscadores como o Google.
Open Graph (OG)
Padrão de meta tags utilizado por redes sociais para gerar previews de links compartilhados com imagem, título e descrição.
Favicon
Pequeno ícone exibido na aba do navegador, favoritos e atalhos do sistema operacional.
Responsividade
Capacidade de uma página se adaptar corretamente a diferentes tamanhos de tela, como celular, tablet e desktop.
Viewport
Configuração responsável por controlar como a página será exibida em dispositivos móveis. Geralmente definida usando a meta tag viewport.
Accessibility (Acessibilidade)
Práticas que tornam o site utilizável por pessoas com deficiência, incluindo leitores de tela, navegação por teclado e descrições alternativas.
Hyperlink
Link clicável criado com a tag <a>, utilizado para navegar entre páginas, sites ou seções do documento.
