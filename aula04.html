Seção 01

O que é
JavaScript

JavaScript é a linguagem que dá vida às páginas web. Se o HTML é a estrutura e o CSS é a aparência, o JavaScript é o comportamento — é ele que faz botões responderem, conteúdo mudar dinamicamente e aplicações inteiras rodarem no navegador. É uma das linguagens mais usadas do mundo e a base de todo o desenvolvimento web moderno.

O que é JavaScript?

JavaScript é uma linguagem de alto nível executada por motores modernos dos navegadores, que utilizam interpretação, compilação JIT e otimizações em tempo real. Criada em 1995 por Brendan Eich enquanto trabalhava na Netscape. O objetivo era simples: permitir que páginas web reagissem às ações do usuário de forma dinâmica, sem depender apenas da renderização tradicional do servidor. Hoje, ela vai muito além disso.

Sua especificação oficial chama-se ECMAScript — mantida pela organização ECMA International. A partir do ES6 (ECMAScript 2015), a linguagem recebeu uma grande atualização com arrow functions, classes, módulos e dezenas de recursos que tornaram o JavaScript moderno muito mais poderoso e legível.

Conceitos fundamentais

Antes de escrever a primeira linha, é importante entender como o JavaScript funciona por baixo dos panos — do ECMAScript ao motor que executa o código:

ECMAScript
O padrão da linguagem
ECMAScript é a especificação oficial do JavaScript, mantida pela ECMA International. Cada versão (ES6, ES2020, ES2024…) adiciona novos recursos à linguagem. Os navegadores implementam esse padrão nos seus motores — o V8 no Chrome, o SpiderMonkey no Firefox.
Interpretada / JIT
Como o código é executado
JavaScript não é compilada antes de rodar — ela é interpretada em tempo de execução. Os motores modernos usam compilação Just-In-Time (JIT): analisam o código enquanto executa e otimizam os trechos mais usados, tornando o JS extremamente rápido.
No navegador
Ambiente nativo do JavaScript
Todo navegador moderno tem um motor JavaScript embutido. O código JavaScript é executado no navegador do usuário, após ser carregado pela aplicação web. O navegador também expõe APIs como o DOM, fetch, localStorage e Web APIs que o JavaScript pode usar para interagir com a página.
JavaScript moderno
A linguagem desde ES6+
O ES6 (2015) marcou uma virada: arrow functions, classes, destructuring, módulos, Promises e muito mais. A linguagem ganhou uma nova cara. Hoje, o JavaScript evolui com atualizações anuais do ECMAScript, que adicionam novos recursos continuamente à linguagem.

A tríade da web: HTML + CSS + JS

Toda página web é construída sobre três tecnologias que trabalham juntas. Cada uma tem um papel bem definido — e o JavaScript é a que traz comportamento e dinamismo:

🏗️
HTML
Estrutura

Define o quê existe na página. Títulos, parágrafos, botões, imagens, formulários. O esqueleto do documento.

🎨

Onde o JavaScript pode rodar

O JavaScript nasceu no navegador, mas hoje roda em praticamente qualquer lugar. O surgimento do Node.js levou a linguagem para fora do browser e abriu um universo inteiro de possibilidades:

Navegador
O ambiente original
Todos os navegadores modernos executam JavaScript nativamente. O código acessa o DOM para manipular a página, as Web APIs para geolocalização, câmera e armazenamento, e o fetch para se comunicar com servidores. Nenhuma instalação necessária.
Node.js
JavaScript no servidor
Criado em 2009, o Node.js levou o motor V8 do Chrome para fora do navegador. Com ele, JavaScript roda no servidor, lê arquivos, acessa bancos de dados e cria APIs. A linguagem virou full-stack — o mesmo código serve tanto para o front-end quanto para o back-end.

JavaScript atua nos dois lados da aplicação, mas com papéis e ferramentas bem distintos. A tabela abaixo resume as principais diferenças:

O papel do JavaScript

No front-end, JavaScript é responsável por tudo que muda e reage na página. Sem ele, os sites seriam documentos estáticos — como livros digitais. Com ele, tornam-se aplicações:

Interatividade
Resposta às ações do usuário
Cliques, hovers, digitação, scroll, drag-and-drop. JavaScript captura eventos e responde a eles em tempo real — sem precisar recarregar a página. É o que torna possível menus, modais, sliders, formulários com validação ao vivo e interfaces ricas.
DOM dinâmico
Atualização do conteúdo
JavaScript pode criar, modificar ou remover qualquer elemento HTML da página sem recarregamento. Feed de redes sociais que carrega mais posts ao rolar, resultados de busca em tempo real, notificações que aparecem — tudo isso é manipulação dinâmica do DOM.
Comunicação
Dados em tempo real
Com fetch e XMLHttpRequest, JavaScript busca e envia dados para servidores em segundo plano. É o que permite salvar um formulário, buscar um CEP, carregar um mapa ou receber mensagens de chat — tudo sem sair da página.
Frameworks
A base de React, Vue e Angular
React, Vue, Angular e Svelte são bibliotecas e frameworks JavaScript. Eles não substituem a linguagem — a estendem. Aprender JavaScript primeiro é fundamental: quem entende os fundamentos aprende qualquer framework em semanas, não meses.

Seção 02

Como conectar
JavaScript

Antes de escrever uma linha de código, você precisa saber como o navegador carrega o JavaScript. A forma como você inclui o <script> na página determina a ordem de execução, o desempenho e até se o código vai funcionar corretamente — ou não.

As três formas de incluir JavaScript

Existem três maneiras de conectar JavaScript a um documento HTML. Cada uma tem seu caso de uso — mas na prática profissional, uma delas domina:

Inline
Diretamente no elemento
Código JS escrito dentro de atributos do HTML como onclick="...". Mistura estrutura e comportamento no mesmo lugar — evite sempre que possível. Dificulta manutenção e impede reutilização.
Interno
Dentro da tag <script>
Código JS escrito diretamente no HTML, entre tags <script></script>. Útil para scripts pequenos e específicos de uma página. Não é reutilizável em outros arquivos.
Externo ✅
Arquivo .js separado
O código fica em um arquivo .js independente, referenciado pelo atributo src. É a abordagem profissional: separa responsabilidades, permite cache do navegador e reutilização em múltiplas páginas.
comparação visual — as três formas de incluir JS
❌ Inline
<button onclick="alert('oi')" >Clique</button>
🟡 Interno
<script> const x = 1; </script>
✅ Externo
<script src="script.js" defer ></script>

Onde posicionar o <script>

A posição do <script> no HTML tem impacto direto na ordem de carregamento e na experiência do usuário. O navegador processa o HTML de cima para baixo — e para tudo quando encontra um <script> sem atributos especiais:

<head>
⚠️ <script src="..."></script> — bloqueia o HTML antes de renderizar
<body>
… conteúdo da página (HTML) …
</body>
✅ <script src="..."></script> — HTML já carregou, DOM disponível
💡 Colocar o <script> antes do </body> era a solução clássica para garantir que o DOM estivesse pronto. Hoje, os atributos defer e async permitem manter o script no <head> sem bloquear o carregamento — e com controle total sobre a ordem de execução.

defer e async — o carregamento inteligente

Esses dois atributos mudam como e quando o script é baixado e executado em relação ao parsing do HTML. Entender a diferença é fundamental para escrever páginas performáticas:

defer ✅ recomendado
Baixa em paralelo, executa depois
O script é baixado em paralelo com o parsing do HTML, mas só executa depois que o documento inteiro foi lido. A ordem entre múltiplos scripts é preservada. Use sempre que o script precisar acessar o DOM ou depender de outro script.
async — use com cuidado
Baixa em paralelo, executa imediatamente
O script é baixado em paralelo, mas executa assim que termina o download — interrompendo o HTML se necessário. A ordem não é garantida. Ideal apenas para scripts totalmente independentes, como analytics e tracking.

💡 Com defer, os scripts ficam no <head> mas o HTML não é bloqueado. O navegador baixa todos os arquivos .js em paralelo enquanto lê o HTML, e só executa cada script — na ordem declarada — após o documento estar completamente parseado. É o melhor dos dois mundos.

Impacto na performance

A forma como você carrega JavaScript afeta diretamente o tempo que o usuário espera para ver e interagir com a página. As métricas do navegador mais impactadas são:

FCP — First Contentful Paint
Tempo até o primeiro conteúdo
Scripts bloqueantes no <head> atrasam o FCP — o navegador para de renderizar até terminar de baixar e executar o JS. Com defer, o HTML renderiza normalmente e o FCP melhora de forma significativa.
TTI — Time to Interactive
Tempo até a página responder
O TTI mede quando a página está pronta para interação. defer garante que o JS executa só quando o DOM está pronto, evitando erros de elemento não encontrado e tornando a inicialização mais previsível.
Prática Impacto Recomendação
Script bloqueante no <head> Atrasa renderização inteira ❌ Evitar
Script no final do <body> HTML renderiza antes, mas download é tardio 🟡 Aceitável
defer no <head> Download paralelo + execução ordenada após HTML ✅ Padrão recomendado
async para scripts independentes Download paralelo + execução não bloqueante ✅ Para analytics e afins
Dividir em múltiplos arquivos pequenos Cache granular + downloads paralelos ✅ Em produção com bundler
🚀 A regra de ouro: use <script src="..." defer></script> no <head> para todos os scripts da sua aplicação. Reserve async apenas para scripts que não dependem do DOM e não dependem de outros scripts — como pixels de rastreamento e ferramentas de analytics.
Seção 03

Variáveis e
Tipos de Dados

Variáveis são a memória do seu programa — onde você guarda, nomeia e manipula informação. Mas em JavaScript, a forma como você declara uma variável define seu comportamento, escopo e até seus limites. Entender isso é a base de tudo que vem depois.

Declaração: var, let e const

JavaScript possui três palavras-chave para declarar variáveis. Cada uma tem regras diferentes de escopo, reatribuição e comportamento em tempo de execução. Na prática moderna, duas delas dominam:

var — legado
Escopo de função
Declaração mais antiga do JS. Tem escopo de função (não de bloco), sofre hoisting e permite redeclaração — comportamentos que geram bugs difíceis de rastrear. Evite em código moderno.
let ✅ reatribuível
Escopo de bloco
Introduzida no ES6. Tem escopo de bloco ({ }), não permite redeclaração no mesmo escopo, mas permite reatribuição. Use quando o valor precisa mudar ao longo do tempo.
const ✅ padrão
Escopo de bloco, vínculo fixo
Também do ES6. Tem escopo de bloco e não permite reatribuição do vínculo. É o padrão recomendado: deixa claro que aquela referência não será substituída. Para objetos e arrays, o conteúdo ainda pode mudar.
comparação visual — as três formas de declarar variáveis
⚠️ var
var nome = 'JS'; // escopo de função, sofre hoisting
🔵 let
let contador = 0; // bloco, reatribuível
✅ const
const PI = 3.14; // bloco, vínculo fixo — padrão

const com Objetos — vínculo fixo, conteúdo mutável

const impede a reatribuição do vínculo — ou seja, você não pode apontar a variável para outro valor. Mas o conteúdo de objetos e arrays declarados com const ainda pode ser modificado livremente. Isso surpreende muita gente:

✅ Isso funciona
Modificar o conteúdo interno
const não congela o objeto — só garante que a variável sempre aponta para o mesmo objeto. Você pode adicionar, modificar e remover propriedades.

user.nome = 'Ana' // ✅ ok
❌ Isso lança erro
Reatribuir o vínculo
O que é proibido é apontar a variável para um novo valor — um novo objeto, array, número, string. O vínculo é fixo desde a declaração.

user = {} // ❌ TypeError
📦Exemplos — const com objetos e arrays
▼
js — const com objetos 
const user = { nome: 'Anderson', idade: 28 };

// ✅ Conteúdo pode mudar — const não congela o objeto
user.nome = 'Ana';
user.email = 'ana@email.com';
delete user.idade;
console.log(user); // { nome: 'Ana', email: 'ana@email.com' }

// ❌ Reatribuição do vínculo — isso lança TypeError
user = {}; // TypeError: Assignment to constant variable

// ── Arrays com const ─────────────────────────────
const cores = ['vermelho', 'verde'];
cores.push('azul');    // ✅ ok
cores[0] = 'roxo';     // ✅ ok
cores = [];            // ❌ TypeError

// Para realmente imutabilizar: Object.freeze()
const config = Object.freeze({ host: 'localhost', porta: 3000 });
config.porta = 8080; // silenciosamente ignorado (ou TypeError em strict mode)
console.log(config.porta); // 3000 — não mudou
💡 const não é imutabilidade — é imutabilidade de vínculo. Para tornar um objeto realmente imutável, use Object.freeze(). Para imutabilidade profunda (nested objects), bibliotecas como Immer ou Immutable.js são a solução adequada.

Escopo e Hoisting

Escopo define onde uma variável pode ser acessada no código. Hoisting é o comportamento do JavaScript de "elevar" declarações ao topo do seu contexto antes de executar — e entender isso explica muitos bugs misteriosos com var:

var — função
⚠️ Visível em toda a função — ignora blocos if, for, while
let/const — bloco
✅ Visível apenas dentro do { } onde foi declarada — previsível e seguro
hoisting
var é elevada e inicializada como undefined. let e const são elevadas mas não inicializadas — acessar antes da declaração lança ReferenceError (Temporal Dead Zone).

Temporal Dead Zone (TDZ)

A Temporal Dead Zone é o período entre o início do bloco e a linha onde let ou const são declaradas. Durante esse período, a variável existe no escopo (foi "içada"/hoisted), mas acessá-la lança um ReferenceError. É uma proteção intencional do ES6 contra bugs de hoisting.

temporal dead zone — diagrama de linha do tempo
INÍCIO DO BLOCO
A variável x existe no escopo (foi içada), mas não tem valor ainda.
⛔ ZONA MORTA (TDZ)
// Qualquer acesso aqui lança:
console.log(x); // ❌ ReferenceError: Cannot access 'x' before initialization
✅ LINHA DE DECLARAÇÃO
let x = 42; // TDZ termina aqui — x agora existe com valor
APÓS DECLARAÇÃO
Acesso livre — console.log(x) → 42
🔍Exemplos — escopo de bloco e hoisting
▼
js — escopo e hoisting 
// ── Escopo de função (var) ──────────────────────
function exemploVar() {
  if (true) {
    var mensagem = 'Olá'; // declarada dentro do if
  }
  console.log(mensagem); // ⚠️ 'Olá' — var vaza do bloco!
}

// ── Escopo de bloco (let / const) ───────────────
function exemploLet() {
  if (true) {
    let mensagem = 'Olá'; // declarada dentro do if
  }
  console.log(mensagem); // ❌ ReferenceError: fora do bloco
}

// ── Hoisting com var ────────────────────────────
console.log(x); // ⚠️ undefined — var foi elevada, mas sem valor
var x = 10;
console.log(x); // 10

// ── Temporal Dead Zone com let ───────────────────
console.log(y); // ❌ ReferenceError: Cannot access 'y' before init
let y = 20;

Tipagem Dinâmica — JavaScript em tempo de execução

JavaScript é uma linguagem de tipagem dinâmica: o tipo de uma variável não é definido na declaração — ele é determinado pelo valor atribuído em tempo de execução. Isso significa que a mesma variável pode conter diferentes tipos ao longo do programa:

⚡Exemplo — tipagem dinâmica em ação
▼
js — tipagem dinâmica 
let dado = 42;
console.log(typeof dado); // "number"

dado = 'texto agora';
console.log(typeof dado); // "string"

dado = true;
console.log(typeof dado); // "boolean"

// O tipo muda conforme o valor — sem erro de compilação

Coerção Implícita — Type Coercion

Coerção é a conversão automática de tipos que o JavaScript realiza quando operadores encontram valores de tipos diferentes. Entender quando ela ocorre é fundamental para evitar bugs silenciosos — especialmente com o operador + e comparações com ==:

✅ '5' - 1

'10' * 2 → 20 // idem
⚠️ null == undef
null == undefined → true // única exceção onde == tem uso legítimo

Funções como First-Class Citizens

Em JavaScript, funções são valores de primeira classe (first-class citizens): elas podem ser armazenadas em variáveis, passadas como argumentos para outras funções e retornadas como resultado. Isso é a base de padrões como callbacks, higher-order functions e programação funcional:

Armazenada em variável
Funções como valores
Uma função pode ser atribuída a qualquer variável como qualquer outro valor. Você pode declarar com function ou como arrow function (=>).

const somar = (a, b) => a + b
Passada como argumento
Callbacks
Funções podem ser passadas para outras funções como parâmetros. O receptor chama essa função quando necessário — esse padrão se chama callback.

[1,2,3].map(dobrar)
Retornada de função
Higher-order functions
Funções que recebem ou retornam outras funções são chamadas de higher-order functions. Permitem criar funções customizáveis e fábricas de comportamento.

const mult = n => x => x * n

Quando uma expressão tem múltiplos operadores, o JavaScript segue regras de precedência (como na matemática: multiplicação antes de soma). Operadores com maior precedência são avaliados primeiro. Use parênteses para deixar a intenção explícita e evitar surpresas:

↑ == != === !== 1 + 1 === 2 true

Operadores Lógicos e Short-Circuit

Combinam ou invertem expressões booleanas. Em JavaScript, && e || não retornam apenas true/false — eles retornam um dos operandos originais. Isso habilita padrões muito úteis na prática:

&& — AND
Verdadeiro se ambos forem
Retorna o primeiro valor falsy ou o último se todos truthy. Se o primeiro for falsy, o segundo nem é avaliado.

true && 'olá' → 'olá'
false && 'olá' → false
|| — OR
Verdadeiro se ao menos um for
Retorna o primeiro valor truthy ou o último se todos falsy. Se o primeiro for truthy, o segundo nem é avaliado.

null || 'padrão' → 'padrão'
'valor' || 'padrão' → 'valor'
! — NOT
Inverte o valor booleano
Converte para booleano e inverte. O duplo !! converte qualquer valor para boolean explicitamente.

!true → false
!!0 → false · !!'texto' → true

Cuidado: misturar ?? com ||

|| usa a lista completa de falsy values para decidir o fallback. ?? só ativa o fallback para null e undefined. A diferença é crítica quando seu valor pode ser 0, '' ou false — valores que são falsy mas semanticamente válidos. Misturar os dois sem cuidado é uma fonte comum de bugs:

|| vs ?? — quando cada um dispara
⚠️||
0 || 3000 → 3000 ⚠️ 0 é falsy — bug se porta=0 era válido
'' || 'padrão' → 'padrão' ⚠️ string vazia pode ser válida
false || 'valor' → 'valor' ⚠️ false pode ser intencional
✅??
0 ?? 3000 → 0 // 0 é válido — não dispara
'' ?? 'padrão' → '' // string vazia é válida — não dispara
null ?? 'padrão' → 'padrão' // só null/undefined dispara

// ── Coalescência Nula (??) — caso clássico ───────
const config = { timeout: 0, nome: null };

const t1 = config.timeout || 5000;  // ⚠️ 5000 — 0 é falsy, bug!
const t2 = config.timeout ?? 5000;  // ✅ 0  — ?? respeita o zero
console.log(t1, t2); // 5000  0

const n = config.nome ?? 'Anônimo';
console.log(n); // 'Anônimo' — null dispara o fallback

// ── Encadeamento Opcional (?.) ───────────────────
const user = { perfil: { cidade: 'Floripa' } };
const userSemPerfil = null;

console.log(user?.perfil?.cidade);           // 'Floripa'
console.log(userSemPerfil?.perfil?.cidade);  // undefined — sem erro!

// ── Combinando ?. com ?? ──────────────────────────
const cidade = user?.perfil?.cidade ?? 'Cidade não informada';
console.log(cidade); // 'Floripa'

Seção 05

Condições
em JavaScript

Condições são o mecanismo de decisão do código — elas determinam quais instruções serão executadas com base no estado do programa. Dominar if/else if/else, o switch com suas armadilhas de fall-through e os padrões modernos de early return é o que transforma código linear em lógica real, capaz de responder a qualquer situação.

O que são Condições?

Em programação, condições permitem que o código tome decisões. Em vez de executar sempre as mesmas instruções, o programa avalia uma expressão que resulta em true ou false e escolhe diferentes caminhos de execução. Esse mecanismo é chamado de fluxo condicional:

Autenticação
Se a senha estiver correta
→ permitir acesso ao sistema.
Caso contrário → bloquear e registrar tentativa.
Validação
Se a idade for maior que 18
→ liberar cadastro completo.
Caso contrário → solicitar autorização dos responsáveis.
Estado
Se o estoque estiver vazio
→ exibir aviso de indisponibilidade.
Caso contrário → mostrar botão de compra.

O JavaScript executa o código de cima para baixo. Quando encontra uma estrutura condicional, avalia a expressão entre parênteses — se resultar em um valor truthy, o bloco é executado; se resultar em falsy, é ignorado. Conhecer a lista completa de valores falsy do JS é fundamental:

Valor Tipo É falsy? Observação
false boolean ✅ Sim O próprio valor booleano false
0 / -0 / 0n number / BigInt ✅ Sim Zero em qualquer representação numérica
'' / "" / `` string ✅ Sim String completamente vazia
null object ✅ Sim Ausência intencional de valor
undefined undefined ✅ Sim Variável declarada mas não inicializada
NaN number ✅ Sim Resultado de operação matemática inválida
'0' / 'false' string ❌ Não (truthy!) Strings não vazias são sempre truthy — cuidado!
[] / {} object ❌ Não (truthy!) Arrays e objetos vazios são truthy — armadilha clássica

Estrutura if

A instrução if é a forma mais básica de controle de fluxo. Executa um bloco somente quando a condição for truthy. As chaves { } são tecnicamente opcionais para uma única linha, mas omiti-las é uma má prática — sempre use chaves para evitar bugs silenciosos:

estrutura if — sintaxe e variações
if básico
if (temperatura > 30) {
  console.log('Está quente');
}
⚠️ sem chaves
if (ativo)
  console.log('ok');
  console.log('sempre executa!'); // ⚠️ fora do if — bug silencioso

if / else / else if — múltiplos caminhos

O else define um caminho alternativo quando a condição é falsa. O else if encadeia múltiplas condições — o JavaScript as avalia de cima para baixo e executa apenas o primeiro bloco cuja condição seja verdadeira. Os demais são ignorados, mesmo que também fossem verdadeiros:

🔀 Exemplos — if, else if e else na prática
▼
js — if / else if / else 
// ── if simples ───────────────────────────────────
let temperatura = 35;

if (temperatura > 30) {
  console.log('Está quente'); // executado
}

// ── if / else ─────────────────────────────────────
let idade = 16;

if (idade >= 18) {
  console.log('Pode dirigir');
} else {
  console.log('Não pode dirigir'); // executado
}

// ── else if — apenas o primeiro match executa ─────
let nota = 7;

if (nota >= 9) {
  console.log('Excelente');
} else if (nota >= 7) {
  console.log('Aprovado');   // executado — 7 >= 7 ✅
} else if (nota >= 5) {
  console.log('Recuperação'); // ignorado — já houve match acima
} else {
  console.log('Reprovado');
}

// ── Condições com operadores lógicos ──────────────
let usuario = { logado: true, admin: false, moderador: true };

if (usuario.logado && (usuario.admin || usuario.moderador)) {
  console.log('Acesso ao painel liberado'); // executado
}

Condições Aninhadas e Early Return

Condições podem existir dentro de outras condições — mas aninhamento excessivo é um sinal de código difícil de manter. A técnica de early return (ou guard clause) inverte a lógica: trata os casos inválidos primeiro e retorna cedo, eliminando o aninhamento e deixando o caminho feliz no nível raiz da função:

❌ Aninhamento excessivo
Pirâmide da Perdição
Cada nível adicional de indentação aumenta a carga cognitiva. Com 3 ou mais níveis, fica difícil rastrear qual condição corresponde a qual bloco.

if (a) { if (b) { if (c) { ... } } }
✅ Early Return
Guard Clauses — rejeite cedo
Trate os casos de erro/borda primeiro com return imediato. O restante da função fica no nível raiz — linear, sem aninhamento.

if (!a) return; if (!b) return; // lógica principal
🏗️ Exemplos — aninhamento vs early return
▼
js — refatorando com early return 
// ❌ Ruim — pirâmide da perdição
function processarPedido(usuario, pedido) {
  if (usuario) {
    if (usuario.ativo) {
      if (pedido) {
        if (pedido.itens.length > 0) {
          console.log('Pedido processado!');
        }
      }
    }
  }
}

// ✅ Bom — early return / guard clauses
function processarPedido(usuario, pedido) {
  if (!usuario)               return 'Usuário inválido';
  if (!usuario.ativo)          return 'Conta desativada';
  if (!pedido)                 return 'Pedido inválido';
  if (pedido.itens.length === 0) return 'Carrinho vazio';

  // caminho feliz — código principal sem aninhamento
  console.log('Pedido processado!');
  return { status: 'ok', pedido };
}

Operador Ternário — if/else em uma linha

O operador ternário (? :) é uma forma compacta de expressar um if/else. É ideal para atribuições simples com dois caminhos. A regra de ouro: se precisar de mais de uma linha para ler, use if/else. Nunca aninhe ternários — o ganho de brevidade não compensa a perda de legibilidade:

ternário — uso correto vs abuso
✅ bom uso
// Atribuição simples — ideal para ternário
const status = idade >= 18 ? 'adulto' : 'menor';
const label = ativo ? 'Online' : 'Offline';
⚠️ evite
// Ternário aninhado — ilegível
const resultado = nota >= 9 ? 'Excelente' : nota >= 7 ? 'Bom' : 'Ruim';
// ⬆️ Use if/else if nesses casos

Estrutura switch

O switch é a estrutura ideal quando uma única variável ou expressão é comparada contra múltiplos valores fixos. Internamente, ele usa comparação estrita (===). O break ao final de cada case é essencial — sem ele, ocorre o temido fall-through:

✅ Com break — correto
Cada case executa isoladamente
O break encerra a execução do switch após o case correspondente. Sem ele, o JavaScript continua para o próximo case indiscriminadamente.

case 3: console.log('Terça'); break;
⚠️ Fall-through — armadilha
Execução "cai" para o próximo case
Sem break, todos os cases seguintes ao match também executam. Pode ser intencional para agrupar casos, mas quando acidental é um bug sutil e perigoso.

case 1: log('Um');
case 2: log('Dois'); // também executa!
🔄 Exemplos — switch, fall-through e agrupamento de cases
▼
js — switch completo 
// ── switch básico ────────────────────────────────
let dia = 3;

switch (dia) {
  case 1:  console.log('Domingo');  break;
  case 2:  console.log('Segunda');  break;
  case 3:  console.log('Terça');    break; // ← executado
  case 4:  console.log('Quarta');   break;
  default: console.log('Dia inválido');
}

// ── Fall-through acidental — bug ─────────────────
let numero = 1;
switch (numero) {
  case 1: console.log('Um');   // sem break!
  case 2: console.log('Dois');  // também executa — bug!
}
// Saída: Um  Dois

// ── Fall-through intencional — agrupando casos ────
let diaDaSemana = 'sábado';
switch (diaDaSemana) {
  case 'sábado':
  case 'domingo':
    console.log('Fim de semana'); break;
  default:
    console.log('Dia útil');
}

// ── switch com string e default no meio ───────────
let status = 'pendente';
switch (status) {
  case 'aprovado': console.log('✅ Aprovado'); break;
  case 'rejeitado': console.log('❌ Rejeitado'); break;
  case 'pendente':  console.log('⏳ Aguardando'); break;
  default:          console.log('Status desconhecido');
}
// Saída: ⏳ Aguardando

if ou switch? — quando usar cada um

A escolha entre if e switch não é apenas de estilo — é uma questão de semântica e manutenibilidade. Cada estrutura tem um caso de uso ideal:

Cenário Use if Use switch
Comparação simples de valor — ✅ switch (status)
Intervalos e ranges ✅ if (nota >= 7 && nota < 9) ❌ Não suporta nativamente
Operadores lógicos (&&, ||) ✅ if (a && b || c) ❌ Não aplicável
Múltiplos valores fixos de uma variável ⚠️ Verboso ✅ Mais legível
Agrupar casos com mesma lógica ⚠️ if (a === 1 || a === 2) ✅ Fall-through intencional
Verificação de tipo ou instância ✅ if (typeof x === 'string') ❌ Menos adequado
3 ou mais valores de enum/status ⚠️ Muitos else if ✅ Mais organizado

Boas Práticas e Armadilhas

Condições mal escritas são uma das principais fontes de bugs em JavaScript. Três armadilhas aparecem com frequência em código de produção:

⚠️ Armadilha 1
Truthy/falsy não intuitivo
[] e {} são truthy — um array vazio em if (arr) passa sempre. Use arr.length === 0 para checar se está realmente vazio.

if ([]) → true! ⚠️
if (arr.length === 0) → correto ✅
⚠️ Armadilha 2
Atribuição dentro do if
if (x = 10) atribui 10 a x — sempre será truthy. O erro deveria ser ===. Linters (ESLint) alertam para isso, mas é bom conhecer.

if (x = 10) // atribui, sempre true!
if (x === 10) // compara ✅
⚠️ Armadilha 3
switch sem default
Omitir o default faz o switch silenciosamente não executar nada para valores inesperados. Sempre inclua um default — mesmo que só para logar ou lançar um erro.

default: throw new Error('Valor inválido');

▼

if (itens) {

}
if (itens.length === 0) {
  console.log('array vazio'); // ✅ correto
}

// ── Checar null E undefined com == null ──────────
let valor = null;
if (valor == null) {
  // ✅ único caso justificado para ==
  // pega tanto null quanto undefined de uma vez
  console.log('null ou undefined');
}

// ── Nomes de variável expressivos ─────────────────
const isLoggedIn    = true;
const hasPermission = false;
const isEmpty       = itens.length === 0;

// Fica muito mais legível:

  console.log('Acesso completo');
}

  switch (tipo) {
    case 'admin':  return 'Administrador';

  }
}

// ── Condição como variável nomeada ────────────────
const usuarioValido = usuario !== null && usuario.ativo === true;
const podeFazerPedido = carrinho.length > 0 && saldo >= total;

  finalizarCompra();

Loops e
Repetições

Loops são o motor da automação — permitem executar um bloco de código repetidamente sem escrever linha por linha. Dominar for, while, for…of e forEach, entender quando usar break e continue, e reconhecer as armadilhas de loops infinitos e aninhamento excessivo é o que separa código que processa dados de código que os repete manualmente.

Por que usar loops?

Sem loops, tarefas repetitivas exigem código duplicado e frágil. Com loops, uma única estrutura processa qualquer quantidade de dados — seja 5 ou 5 milhões de itens, o código não muda. Cada execução do bloco interno é chamada de iteração:

sem loop vs com loop — o mesmo resultado, código completamente diferente
❌ sem loop
console.log(1);
console.log(2);
console.log(3); // e se forem 1000 números?
✅ com loop
for (let i = 1; i <= 1000; i++) {
  console.log(i); // funciona para qualquer quantidade
}

Estrutura for

O for é o loop mais utilizado. É ideal quando o número de iterações é conhecido antecipadamente. Sua sintaxe reúne três expressões separadas por ponto e vírgula dentro dos parênteses — cada uma com um papel específico e executado em momentos distintos:

Parte Expressão Quando executa Descrição
Inicialização let i = 0 Uma única vez, antes do loop Declara e define o valor inicial do contador
Condição i < 5 Antes de cada iteração Se false, o loop encerra imediatamente
Incremento i++ Ao final de cada iteração Atualiza o contador para a próxima rodada
Contagem crescente
i++ — padrão
Incrementa de 1 em 1 do início ao fim.

for (let i = 1; i <= 5; i++)
// 1 2 3 4 5
Contagem regressiva
i-- — decremento
Itera de trás para frente, útil para remoções em arrays sem afetar índices.

for (let i = 5; i >= 1; i--)
// 5 4 3 2 1
Passo personalizado
i += N — saltos
Incremento não precisa ser de 1 — qualquer expressão válida funciona.

for (let i = 0; i <= 10; i += 2)
// 0 2 4 6 8 10
🔢 Exemplos — for com arrays, índices e variações de incremento
▼
js — for e suas variações 
// ── for básico ───────────────────────────────────
for (let i = 1; i <= 5; i++) {
  console.log(i); // 1 2 3 4 5
}

// ── Percorrendo array com for ─────────────────────
const frutas = ['Maçã', 'Banana', 'Laranja'];

for (let i = 0; i < frutas.length; i++) {
  console.log(i, frutas[i]); // 0 Maçã / 1 Banana / 2 Laranja
}

// ── Contagem regressiva ───────────────────────────
for (let i = 5; i >= 1; i--) {
  console.log(i); // 5 4 3 2 1
}

// ── Passo personalizado ───────────────────────────
for (let i = 0; i <= 10; i += 2) {
  console.log(i); // 0 2 4 6 8 10
}

// ── Remover itens de array de trás para frente ────
// Remover de frente para trás altera índices durante a iteração — bug!
// A forma correta é iterar de trás para frente:
const nums = [1, 2, 3, 4, 5];
for (let i = nums.length - 1; i >= 0; i--) {
  if (nums[i] % 2 === 0) nums.splice(i, 1); // remove pares
}
console.log(nums); // [1, 3, 5]

Estrutura while

O while executa um bloco enquanto uma condição for verdadeira. É a escolha certa quando não se sabe antecipadamente quantas iterações serão necessárias — o número de repetições depende de uma condição que muda durante a execução. A condição é avaliada antes de cada iteração: se começar falsa, o bloco nunca executa:

while — verifica antes
Condição avaliada no início de cada ciclo
Se a condição já for false na primeira verificação, o bloco não executa nenhuma vez. Use quando a execução é totalmente opcional.

while (contador <= 5) { ... }
Casos de uso ideais
Quando o número de iterações é desconhecido
Leitura de stream de dados, tentativas de conexão, leitura de input do usuário até valor válido, processamento de fila, polling de API até resultado.

while (!conexaoEstabelecida) { tentar(); }
🔁 Exemplos — while em situações reais
▼
js — while e seus padrões 
// ── while básico ─────────────────────────────────
let contador = 1;

while (contador <= 5) {
  console.log(contador); // 1 2 3 4 5
  contador++;              // ← obrigatório! sem isso: loop infinito
}

// ── Condição já falsa — bloco nunca executa ───────
let numero = 10;
while (numero < 5) {
  console.log('nunca executa'); // número já é 10
}

// ── Padrão real: tentativas com limite ────────────
let tentativas  = 0;
let maxTentativas = 3;
let autenticado  = false;

while (!autenticado && tentativas < maxTentativas) {
  tentativas++;
  console.log(`Tentativa ${tentativas}...`);

  if (tentativas === 2) {     // simula sucesso na 2ª tentativa
    autenticado = true;
  }
}

console.log(autenticado ? 'Login OK' : 'Bloqueado'); // Login OK

// ── Processando fila de tarefas ───────────────────
const fila = ['tarefa1', 'tarefa2', 'tarefa3'];

while (fila.length > 0) {
  const tarefa = fila.shift(); // remove o primeiro
  console.log(`Processando: ${tarefa}`);
}
// Processando: tarefa1 / tarefa2 / tarefa3

Estrutura do…while

O do…while é a única estrutura que garante ao menos uma execução — o bloco roda primeiro, a condição é verificada depois. Isso o torna ideal para situações em que a primeira execução é sempre necessária, como exibir um menu, processar input inicial ou tentar uma operação antes de verificar se deve continuar:

while vs do…while — a diferença crítica com condição já falsa
🔄 while verifica antes
let x = 10;
while (x < 5) {
  console.log(x);
}
// (nada acontece — condição já é falsa)
✅ do…while executa antes
let x = 10;
do {
  console.log(x);
} while (x < 5);
// Saída: 10 — executou uma vez mesmo com condição falsa

Estrutura for…of

Introduzido no ES2015, o for…of foi criado especificamente para percorrer iteráveis — arrays, strings, Map, Set e qualquer objeto que implemente o protocolo de iteração. Elimina o gerenciamento manual de índices e torna o código declarativo: você expressa o que fazer com cada item, não como acessá-lo:

Iterável for…of itera sobre… Exemplo
Array Cada valor do array for (const item of ['a','b','c'])
String Cada caractere (Unicode-safe) for (const char of 'JS')
Map Par [chave, valor] for (const [k, v] of mapa)
Set Cada valor único for (const item of conjunto)
NodeList Cada elemento DOM for (const el of document.querySelectorAll('p'))
Object literal ❌ Não iterável — use for…in ou Object.entries() for (const [k,v] of Object.entries(obj))
🌿 Exemplos — for…of com arrays, strings, Map, Set e destructuring
▼
js — for…of em todos os iteráveis 
// ── Array ─────────────────────────────────────────
const frutas = ['Maçã', 'Banana', 'Laranja'];

for (const fruta of frutas) {
  console.log(fruta); // Maçã / Banana / Laranja
}

// ── Array com índice via entries() ────────────────
for (const [indice, fruta] of frutas.entries()) {
  console.log(indice, fruta); // 0 Maçã / 1 Banana / 2 Laranja
}

// ── String — caractere a caractere ───────────────
for (const letra of 'JS') {
  console.log(letra); // J / S
}

// ── Map — destructuring direto ────────────────────
const mapa = new Map([['nome', 'Ana'], ['idade', 30]]);

for (const [chave, valor] of mapa) {
  console.log(`${chave}: ${valor}`); // nome: Ana / idade: 30
}

// ── Set — valores únicos ──────────────────────────
const conjunto = new Set([1, 2, 2, 3, 3]);
for (const item of conjunto) {
  console.log(item); // 1 / 2 / 3 — duplicatas eliminadas
}

// ── Object: use Object.entries() ─────────────────
const usuario = { nome: 'Ana', idade: 30, ativo: true };
for (const [chave, valor] of Object.entries(usuario)) {
  console.log(`${chave}: ${valor}`); // nome: Ana / idade: 30 / ativo: true
}

Método forEach()

O forEach() é um método de array — não uma estrutura de controle, mas uma função de alta ordem que recebe um callback executado para cada elemento. Recebe três argumentos opcionais: o valor atual, o índice e o próprio array. É mais expressivo que o for quando o objetivo é apenas executar um efeito colateral para cada item, sem necessidade de interrupção:

forEach — sintaxe completa e evolução até arrow function
📝 tradicional
frutas.forEach(function(fruta, indice, array) {
  console.log(indice, fruta);
});
✅ arrow
frutas.forEach((fruta, indice) => console.log(indice, fruta));
🚫 sem break
// ⚠️ forEach não suporta break — sempre itera todo o array
// Para interrupção antecipada: use for, for…of ou Array.some()

for vs for…of vs forEach — quando usar cada um

Controle de fluxo: break e continue

Dentro de qualquer loop (for, while, for…of), duas palavras-chave permitem controlar a execução além da condição principal. Usadas com critério, tornam o código mais eficiente; usadas em excesso, dificultam a leitura:

break — encerrar o loop
Interrompe imediatamente toda a estrutura
Ao encontrar break, o loop encerra e a execução continua após o bloco. Útil para parar ao encontrar o primeiro resultado — evita iterações desnecessárias.

if (i === 5) break; // sai do loop
continue — pular a iteração
Pula para o próximo ciclo sem encerrar
Ao encontrar continue, o restante do bloco atual é ignorado e o loop avança para a próxima iteração. Útil para filtrar casos sem aninhar um if/else.

if (i % 2 === 0) continue; // pula pares
⚡ Exemplos — break, continue e labeled loops
▼
js — break, continue e loops rotulados 
// ── break — sai ao encontrar o primeiro par ───────
for (let i = 1; i <= 10; i++) {
  if (i % 2 === 0) {
    console.log(`Primeiro par: ${i}`); // Primeiro par: 2
    break; // para o loop — não percorre os 10 elementos
  }
}

// ── continue — pula os ímpares ────────────────────
for (let i = 1; i <= 5; i++) {
  if (i % 2 !== 0) continue; // pula ímpares
  console.log(i); // 2 / 4
}

// ── break em while — saída por condição interna ───
let tentativas = 0;
while (true) { // loop intencional — saída controlada pelo break
  tentativas++;
  if (tentativas >= 3) break;
}
console.log(`Parou após ${tentativas} tentativas`); // 3

// ── Labeled loops — break no loop externo ─────────
// Útil para sair de loops aninhados sem flags booleanas
externo: for (let i = 0; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (i === 1 && j === 1) break externo; // sai dos dois loops
    console.log(i, j);
  }
}
// 0 0 / 0 1 / 0 2 / 1 0 — parou ao chegar em i=1, j=1

Loops Infinitos e Armadilhas

Um loop infinito ocorre quando a condição de parada nunca se torna falsa — a aba congela, o processo consome 100% da CPU e o único recurso é fechar o navegador ou matar o processo. Três padrões causam a maioria dos loops infinitos acidentais:

⚠️ Armadilha 1
Esqueceu o incremento
A variável de controle nunca muda — a condição nunca se torna falsa. Causa mais comum em while loops.

while (i <= 5) { log(i); } // sem i++!
⚠️ Armadilha 2
Condição sempre verdadeira
Comparação com !== pode nunca chegar ao valor exato por ponto flutuante ou lógica incorreta.

while (x !== 1) { x += 0.3; } // nunca será exatamente 1
⚠️ Armadilha 3
Modificando o array durante a iteração
Adicionar itens a um array dentro de um for que usa .length como condição aumenta o limite a cada iteração.

for (let i=0; i<arr.length; i++) { arr.push(x); }
♾️ Exemplos — loops infinitos e como evitá-los
▼
js — loops infinitos, causas e correções

let contador = 1;

  console.log(contador);
  // contador++ esquecido → condição nunca muda
}

// ✅ Correto

  console.log(contador);
  contador++; // ← obrigatório

// ❌ Loop infinito — ponto flutuante

// ✅ Correto — use < ou <= com floats

  x += 0.1;
}

// ❌ Loop infinito — modificando o array durante for

  // length fixo — seguro
}

// ✅ while(true) intencional — com break garantido

  const resultado = tentarConexao();
  if (resultado.ok) break; // saída garantida

});

// ✅ for...of aguarda cada iteração (sequencial)

  const dado = await buscarUsuario(id); // correto
  console.log(dado);
}

// ✅ Promise.all para execução paralela

// ── Loop aninhado O(n²) → refatorado com Map ──────
const usuarios  = [{ id: 1, nome: 'Ana' }, { id: 2, nome: 'Bob' }];
const pedidos   = [{ userId: 1, item: 'livro' }, { userId: 2, item: 'caneta' }];

// ❌ O(n²) — para cada pedido, percorre todos os usuários
for (const pedido of pedidos) {
  for (const usuario of usuarios) {
    if (usuario.id === pedido.userId) console.log(usuario.nome, pedido.item);
  }
}

// ✅ O(n) — Map para lookup instantâneo
const mapaUsuarios = new Map(usuarios.map(u => [u.id, u]));
for (const pedido of pedidos) {
  const usuario = mapaUsuarios.get(pedido.userId);
  if (usuario) console.log(usuario.nome, pedido.item);
}

Funções
em JavaScript

Funções são a unidade fundamental de abstração do JavaScript — blocos reutilizáveis que encapsulam lógica, recebem dados, processam e devolvem resultados. Dominar declarações, expressões, arrow functions, entender escopo, hoisting, closures e o papel das funções como cidadãs de primeira classe é o que transforma código procedural em arquitetura modular e testável.

Anatomia de uma Função

Toda função tem partes bem definidas. Entender o papel de cada uma é o primeiro passo para escrever funções corretas e previsíveis:

Parte Exemplo Obrigatório? Descrição
Palavra-chave function ✅ Sim (na declaração) Sinaliza ao JS que um bloco de função está sendo definido

Parâmetros vs Argumentos

São conceitos distintos que frequentemente causam confusão. A diferença é simples: parâmetros existem na definição, argumentos existem na chamada. Além disso, o JavaScript tem comportamentos específicos quando a quantidade de argumentos não bate com a de parâmetros:

parâmetros vs argumentos — definição vs chamada
📋 parâmetros na definição
function somar(a, b) {
  return a + b;
}
// a e b são PARÂMETROS — variáveis locais da função
📨 argumentos na chamada
somar(10, 20);
// 10 e 20 são ARGUMENTOS — valores passados à função
⚠️ menos args
somar(10); // b recebe undefined → retorna NaN
// JS não lança erro — parâmetros ausentes viram undefined
📦 mais args
somar(10, 20, 30); // 30 é ignorado silenciosamente
// Argumentos extras ficam acessíveis via ...rest ou arguments

O poder do return

O return faz duas coisas simultaneamente: devolve um valor ao chamador e encerra imediatamente a execução da função. Todo código após um return é código morto — nunca executará. Funções sem return explícito devolvem undefined automaticamente:

❌ console.log — efeito colateral
Apenas exibe — não devolve
O resultado some no console. Não pode ser armazenado, reutilizado ou composto com outras funções. Adequado apenas para depuração.

function somar(a, b) { console.log(a + b); }
const x = somar(1, 2); // x === undefined!
✅ return — valor reutilizável
Devolve — pode ser composto
O resultado pode ser armazenado, passado para outra função, somado, exibido — qualquer coisa. É a forma correta para funções de cálculo.

function somar(a, b) { return a + b; }
const dobro = somar(1, 2) * 2; // 6 ✅

Hoisting — o que sobe e o que não sobe

Hoisting é o mecanismo pelo qual o JavaScript processa declarações antes de executar o código. Function declarations são içadas completamente — nome e corpo. Variáveis const/let são içadas mas permanecem em Temporal Dead Zone até a linha de declaração, causando ReferenceError se acessadas antes:

hoisting — o que o JS faz antes de executar seu código
✅ declaration
içamento total

🚫 expression
arrow — TDZ
saudar(); // ❌ ReferenceError — está na Temporal Dead Zone
somar(1, 2); // ❌ ReferenceError

const saudar = function() { ... };
const somar = (a, b) => a + b;

Escopo: Global, Local e Léxico

Escopo define a visibilidade e o tempo de vida de uma variável. JavaScript tem três níveis relevantes para funções — e o entendimento do escopo léxico é a base para compreender closures:

Escopo Global
Acessível em qualquer lugar
Variáveis declaradas fora de qualquer função ou bloco. Visíveis em todo o script. Evite poluir o escopo global — gera acoplamento e conflitos em projetos grandes.

let app = 'MyApp'; // global
Escopo Local (função)
Existe apenas dentro da função
Variáveis criadas com let/const dentro de uma função não existem fora dela. Acessá-las externamente gera ReferenceError.

function fn() { let x = 1; } // x é local
Escopo Léxico
Função enxerga onde foi criada
Uma função interna acessa variáveis do escopo onde foi definida, não onde é chamada. Isso é a base das closures.

function externa() { let x = 1;
 function interna() { return x; } }
🔭 Exemplos — escopo, shadowing e acesso incorreto
▼

Cidadãs de Primeira Classe e Callbacks

Em JavaScript, funções são valores como qualquer outro — podem ser atribuídas a variáveis, passadas como argumentos e retornadas por outras funções. Essa característica é chamada de first-class functions e é o que torna possível o padrão de callback — pilar de toda a programação assíncrona e dos métodos de array modernos:

Armazenar em variável
Funções são valores
Uma função pode ser guardada em const, let, propriedade de objeto ou elemento de array.

const fn = function() { ... };
const obj = { metodo: fn };
Passar como argumento
Callbacks
Uma função passada para outra função para ser chamada em algum momento — imediatamente, após um evento ou operação assíncrona.

btn.addEventListener('click', handler);
Retornar de outra função
Higher-order functions
Funções que recebem ou retornam outras funções. Base de closures, currying e do padrão factory.

function criar(x) { return (y) => x + y; }

  total:     () => itens.length,
  listar:    () => [...itens], // retorna cópia, não a referência
};
}

Funções Puras vs Efeitos Colaterais

Um conceito fundamental para código previsível e testável. Uma função pura tem duas características: dado o mesmo input, sempre retorna o mesmo output — e não produz efeitos colaterais (não modifica variáveis externas, não faz I/O, não muda o estado do mundo):

função pura vs impura — previsibilidade e testabilidade
⚠️ impura
let total = 0;
function adicionar(n) {
  total += n; // efeito colateral — modifica variável externa
}
// resultado depende do estado externo — difícil de testar
✅ pura
function somar(total, n) {
  return total + n; // sem efeito colateral
}
// somar(0, 5) sempre → 5. Fácil de testar e compor.

Boas Práticas e Princípios

Funções bem escritas são a diferença entre uma base de código que cresce saudável e uma que vira legado em meses. Quatro princípios definem a maioria das boas decisões:

✅ Single Responsibility
Uma função, uma responsabilidade
Se você precisar usar "e" para descrever o que a função faz, ela faz coisas demais. Divida em funções menores, cada uma focada em uma única tarefa.

validarPedido() / calcularTotal() / enviarEmail()
✅ return > console.log
Prefira retornar valores
console.log é efeito colateral — o resultado some. Com return, o chamador decide o que fazer com o valor: exibir, somar, passar para outra função.

function somar(a, b) { return a + b; }
✅ Nomes descritivos
Funções são verbos, variáveis são substantivos
O nome deve revelar a intenção. Prefira verbos claros: calcular, validar, buscar, criar. Booleans retornados: prefixe com is/has/can.

isAdmin() / hasPermission() / calcularTotal()
✅ Funções pequenas
Se não cabe na tela, está grande demais
Funções pequenas são mais fáceis de ler, testar, reutilizar e depurar. O tamanho ideal gira em torno de 10–20 linhas. Funções muito longas geralmente têm responsabilidades demais.

Índices e Acesso aos Elementos

Cada elemento de um array possui uma posição (índice). O índice sempre começa em 0. Usamos colchetes [] para acessar ou alterar um elemento específico:

Índice Elemento Acesso Resultado
0 Primeiro frutas[0] "Maçã"
1 Segundo frutas[1] "Banana"
2 Terceiro frutas[2] "Laranja"
length - 1 Último frutas[frutas.length - 1] "Laranja"
🔍 Exemplos — acessando e alterando elementos
▼
js — índices, acesso e alteração 
const frutas = ["Maçã", "Banana", "Laranja"];

// Acessando elementos pelo índice
console.log(frutas[0]); // "Maçã"
console.log(frutas[1]); // "Banana"
console.log(frutas[2]); // "Laranja"

// Tamanho do array
console.log(frutas.length); // 3

// Acessando o último elemento de forma dinâmica
console.log(frutas[frutas.length - 1]); // "Laranja"

// Alterando um valor pelo índice
frutas[1] = "Uva";
console.log(frutas); // ["Maçã", "Uva", "Laranja"]

Adicionando e Removendo: push() e pop()

Os métodos push() e pop() operam no final do array. O push() adiciona um ou mais elementos; o pop() remove o último e o retorna:

push() — adiciona
Insere ao final do array
Aceita um ou mais valores e os adiciona ao final. Modifica o array original.

frutas.push("Uva") → ["Maçã","Banana","Uva"]
frutas.push("Uva","Morango") → adiciona dois
pop() — remove
Remove e retorna o último elemento
Remove o último item e o retorna — útil para capturar o valor removido.

frutas.pop() → remove "Laranja"
const ultima = frutas.pop() → "Laranja"
➕ Exemplos — push() e pop() na prática
▼
js — push() e pop() 
const frutas = ["Maçã", "Banana"];

// push() — adiciona ao final
frutas.push("Laranja");
console.log(frutas); // ["Maçã", "Banana", "Laranja"]

// push() com múltiplos valores
frutas.push("Uva", "Morango");
console.log(frutas); // ["Maçã", "Banana", "Laranja", "Uva", "Morango"]

// pop() — remove o último
frutas.pop();
console.log(frutas); // ["Maçã", "Banana", "Laranja", "Uva"]

// pop() retorna o elemento removido
const ultimaFruta = frutas.pop();
console.log(ultimaFruta); // "Uva"
console.log(frutas);     // ["Maçã", "Banana", "Laranja"]

O Método map()

O map() cria um novo array transformando cada elemento do array original por meio de uma função callback. O array original nunca é modificado:

como o map() funciona
Original
[1, 2, 3]
Callback
numero => numero * 2 // aplicada a cada elemento
Novo array
[2, 4, 6] // original [1,2,3] permanece intacto
🗺️ Exemplos — map() com números e objetos
▼
js — map() 
// Dobrar números
const numeros = [1, 2, 3];

const dobrados = numeros.map(numero => {
return numero * 2;
});

console.log(dobrados); // [2, 4, 6]
console.log(numeros);  // [1, 2, 3] — original intacto

// Extraindo propriedades de objetos
const usuarios = [
{ nome: "Ana" },
{ nome: "Carlos" }
];

const nomes = usuarios.map(usuario => {
return usuario.nome;
});

console.log(nomes); // ["Ana", "Carlos"]

// Forma curta com arrow function implícita
const nomesShort = usuarios.map(u => u.nome);
console.log(nomesShort); // ["Ana", "Carlos"]

O Método filter()

O filter() cria um novo array contendo apenas os elementos que passam em um teste (retornam true na função callback). Elementos que retornam false são descartados:

Retorna true ✅
Elemento permanece no array
Se a condição for verdadeira, o elemento é incluído no novo array resultante.

numero >= 30 → true → fica
Retorna false ❌
Elemento é descartado
Se a condição for falsa, o elemento é ignorado e não entra no novo array.

numero >= 30 → false → descartado
🔽 Exemplos — filter() com números e objetos
▼
js — filter() 
// Filtrando números maiores ou iguais a 30
const numeros = [10, 20, 30, 40];

const maiores = numeros.filter(numero => {
return numero >= 30;
});

console.log(maiores); // [30, 40]

// Filtrando usuários ativos
const usuarios = [
{ nome: "Ana", ativo: true },
{ nome: "Carlos", ativo: false },
{ nome: "Maria", ativo: true }
];

const ativos = usuarios.filter(usuario => {
return usuario.ativo;
});

console.log(ativos);
// [{ nome: "Ana", ativo: true }, { nome: "Maria", ativo: true }]

O Método find()

O find() retorna o primeiro elemento que satisfaz a condição. Diferente do filter(), ele para na primeira ocorrência. Se nada for encontrado, retorna undefined:

Método Retorna Para na 1ª ocorrência? Quando usar
find() O elemento encontrado ou undefined ✅ Sim Buscar um único item por ID ou condição única
filter() Novo array com todos os que passaram ❌ Não Buscar múltiplos itens que atendem a um critério
🎯 Exemplos — find() buscando por id
▼
js — find() 
const usuarios = [
{ id: 1, nome: "Ana" },
{ id: 2, nome: "Carlos" },
{ id: 3, nome: "Maria" }
];

// Busca pelo id 2 — para na primeira ocorrência
const usuario = usuarios.find(item => {
return item.id === 2;
});

console.log(usuario); // { id: 2, nome: "Carlos" }

// Quando nada é encontrado
const resultado = usuarios.find(item => item.id === 999);
console.log(resultado); // undefined

// Boa prática: verificar antes de usar
if (resultado) {
console.log(resultado.nome);
} else {
console.log("Usuário não encontrado");
}

O Método reduce()

O reduce() é um dos mais poderosos dos arrays. Ele reduz vários valores a um único resultado, acumulando o retorno de cada iteração. Recebe uma função callback e um valor inicial:

como o reduce() acumula — passo a passo
Valor Inicial
acumulador = 0
1ª iteração
0 + 10 = 10
2ª iteração
10 + 20 = 30
3ª iteração
30 + 30 = 60
Resultado
60
➕ Exemplos — reduce() com números e objetos
▼
js — reduce() 
// Somando números
const numeros = [10, 20, 30];

const total = numeros.reduce(
(acumulador, numero) => {
  return acumulador + numero;
},
0 // valor inicial
);

console.log(total); // 60

// Calculando total de pedidos (caso real)
const pedidos = [
{ valor: 100 },
{ valor: 200 },
{ valor: 300 }
];

const totalPedidos = pedidos.reduce(
(acumulador, pedido) => {
  return acumulador + pedido.valor;
},
0
);

console.log(totalPedidos); // 600

Encadeando Métodos

Os métodos de array podem ser combinados em sequência. O resultado de um vira a entrada do próximo — poderoso e expressivo:

filter() + map() encadeados
Entrada
[5, 10, 20, 30]
Passo 1 filter()
numero > 10 → [20, 30]
Passo 2 map()
numero * 2 → [40, 60]
Resultado
[40, 60]
⛓️ Exemplos — encadeamento na prática real
▼
js — encadeamento de métodos 
// Encadeando filter() + map()
const numeros = [5, 10, 20, 30];

const resultado = numeros
.filter(numero => numero > 10)  // [20, 30]
.map(numero => numero * 2);       // [40, 60]

console.log(resultado); // [40, 60]

// Caso real: nomes dos usuários ativos em maiúsculo
const usuarios = [
{ nome: "Ana", ativo: true },
{ nome: "Carlos", ativo: false },
{ nome: "Maria", ativo: true }
];

const nomesAtivos = usuarios
.filter(u => u.ativo)
.map(u => u.nome.toUpperCase());

console.log(nomesAtivos); // ["ANA", "MARIA"]

Mutabilidade e Imutabilidade

Arrays são mutáveis — podem ser alterados após a criação. Em React e aplicações modernas, no entanto, prefere-se a abordagem imutável: criar um novo array em vez de modificar o original. Isso evita bugs difíceis de rastrear:

⚠️ Mutável
Modifica o array original
O push() altera diretamente o array. Em React, isso pode causar problemas porque o estado não é "trocado", apenas modificado por dentro.

frutas.push("Laranja") // altera o original
✅ Imutável
Cria um novo array
O spread operator ... copia os elementos existentes e adiciona o novo, preservando o array original completamente intacto.

const novo = [...frutas, "Laranja"]
🔒 Exemplos — mutável vs. imutável na prática
▼
js — mutável vs. imutável 
const frutas = ["Maçã", "Banana"];

// ── Forma MUTÁVEL — altera o original ────────────
frutas.push("Laranja");
console.log(frutas); // ["Maçã", "Banana", "Laranja"] — original modificado!

// ── Forma IMUTÁVEL — cria um novo array ──────────
const frutasOriginais = ["Maçã", "Banana"];
const novasFrutas = [...frutasOriginais, "Laranja"];

console.log(frutasOriginais); // ["Maçã", "Banana"] — intacto!
console.log(novasFrutas);     // ["Maçã", "Banana", "Laranja"]

// Removendo sem alterar o original — com filter()
const numeros = [1, 2, 3, 4];

const semOTres = numeros.filter(n => n !== 3);

console.log(numeros);   // [1, 2, 3, 4] — intacto!
console.log(semOTres); // [1, 2, 4]

Comparativo completo dos Métodos

Resumo dos principais métodos de array e quando usar cada um:

Método O que faz Retorna Altera original? Quando usar
push() Adiciona ao final Novo length ⚠️ Sim Adicionar elemento (imperativo)
pop() Remove do final Elemento removido ⚠️ Sim Remover o último elemento
map() Transforma elementos Novo array ✅ Não Transformar cada elemento
filter() Filtra por condição Novo array ✅ Não Manter apenas elementos válidos
find() Busca o primeiro que passa Elemento ou undefined ✅ Não Buscar um único item
reduce() Acumula em um único valor Qualquer valor ✅ Não Somar, contar, agrupar

Boas Práticas

const sempre
Use const para arrays
O conteúdo do array pode mudar com push() mesmo usando const. Use const para sinalizar que a variável não será reatribuída.

const usuarios = [];
Métodos certos
Prefira map, filter, find
Para transformar use map(), para filtrar use filter(), para buscar um item use find(). Evite loops manuais quando esses métodos resolvem melhor.
Imutabilidade
Prefira criar novos arrays
Evite alterar arrays existentes. Use spread [...arr], map(), filter() e reduce() para criar novas estruturas, especialmente em React.
🚀 As regras de ouro dos Arrays: declare com const sempre que possível; prefira map() para transformar, filter() para filtrar e find() para buscar um único item; use reduce() quando precisar de um único valor a partir de uma lista; combine métodos com encadeamento para código expressivo; e prefira a abordagem imutável — crie novos arrays com spread (...) em vez de modificar os existentes.

Objetos
em JavaScript

Objetos são a estrutura central do JavaScript — praticamente tudo na linguagem é um objeto. Eles permitem representar entidades do mundo real agrupando dados relacionados em pares de chave e valor. Dominar destructuring, spread operator e os métodos Object.keys(), Object.values() e Object.entries() é essencial para trabalhar com APIs e com React de forma profissional.

O que são Objetos?

Objetos armazenam informações relacionadas em pares de chave e valor. Enquanto arrays organizam dados por posição (índice), objetos organizam dados por propriedades nomeadas — o que torna a leitura muito mais intuitiva:

sem objeto vs. com objeto
❌ Sem objeto
const nome = "Anderson";
const idade = 22;
const email = "anderson@email.com";
✅ Com objeto
const usuario = {
  nome: "Anderson",
  idade: 22,
  email: "anderson@email.com"
}; // dados agrupados de forma lógica

Acessando Propriedades

Existem duas formas de acessar propriedades de um objeto. A notação de ponto é a mais comum; a notação de colchetes é usada quando o nome da propriedade é dinâmico (vem de uma variável):

Forma Sintaxe Exemplo Quando usar
Notação de ponto objeto.propriedade usuario.nome ✅ Padrão — nome fixo e conhecido
Notação de colchetes objeto["propriedade"] usuario["nome"] Quando a propriedade vem de uma variável
Colchetes dinâmico objeto[variavel] usuario[chave] Quando o nome da propriedade é calculado
🔑 Exemplos — ponto, colchetes e acesso dinâmico
▼
js — acessando propriedades 
const usuario = {
  nome: "Anderson",
  idade: 22
};

// Notação de ponto — mais comum
console.log(usuario.nome);   // "Anderson"
console.log(usuario.idade);  // 22

// Notação de colchetes — equivalente
console.log(usuario["nome"]);  // "Anderson"

// Colchetes dinâmicos — propriedade em variável
const chave = "nome";
console.log(usuario[chave]);   // "Anderson"

Alterando, Adicionando e Removendo Propriedades

Objetos são mutáveis — você pode alterar valores existentes, adicionar novas propriedades ou remover com o operador delete. Mesmo com const, o conteúdo interno pode mudar — o que não pode é reatribuir a variável:

Alterar
Modifica um valor existente
Basta acessar a propriedade pela notação de ponto e atribuir o novo valor.

usuario.nome = "Carlos"
Adicionar
Cria uma nova propriedade
Se a propriedade não existe, ela é criada automaticamente na atribuição.

usuario.idade = 22
Remover
Exclui a propriedade
O operador delete remove a chave e o valor completamente do objeto.

delete usuario.idade
✏️ Exemplos — alterar, adicionar, remover e const
▼
js — mutabilidade de objetos 
const usuario = { nome: "Anderson", idade: 22 };

// Alterando uma propriedade existente
usuario.nome = "Carlos";
console.log(usuario.nome); // "Carlos"

// Adicionando nova propriedade
usuario.email = "carlos@email.com";
console.log(usuario); // { nome: "Carlos", idade: 22, email: "carlos@email.com" }

// Removendo com delete
delete usuario.idade;
console.log(usuario); // { nome: "Carlos", email: "carlos@email.com" }

// const — o conteúdo pode mudar, a variável não
usuario.nome = "Maria";  // ✅ permitido
usuario = {};              // ❌ TypeError — não pode reatribuir

Métodos e a Palavra-Chave this

Quando uma propriedade armazena uma função, ela é chamada de método. Dentro de métodos, usamos this para acessar as outras propriedades do próprio objeto de forma dinâmica:

o que this representa dentro de um método
this.nome
// equivale a acessar
usuario.nome
Mas de forma dinâmica — torna o método reutilizável independente do nome da variável.
Sintaxes
saudar() { ... } // shorthand — recomendado
saudar: function() { ... } // tradicional — também válido
⚙️ Exemplos — métodos e this na prática
▼
js — métodos e this 
const usuario = {
  nome: "Anderson",

  // Sintaxe shorthand (recomendada)
  saudar() {
    console.log("Olá!");
  },

  // Usando this para acessar o próprio objeto
  apresentar() {
    console.log(`Meu nome é ${this.nome}`);
  },

  // Sintaxe tradicional — também válida
  despedir: function() {
    console.log(`Até logo, ${this.nome}!`);
  }
};

usuario.saudar();     // "Olá!"
usuario.apresentar(); // "Meu nome é Anderson"
usuario.despedir();   // "Até logo, Anderson!"

Destructuring

Destructuring permite extrair propriedades de um objeto de forma concisa, criando variáveis diretamente. Também é possível renomear variáveis, definir valores padrão e desestruturar objetos aninhados:

sem destructuring vs. com destructuring
❌ Verboso
const nome = usuario.nome;
const idade = usuario.idade;
✅ Destructuring
const { nome, idade } = usuario;
// Cria as variáveis nome e idade diretamente
📦 Exemplos — destructuring completo: renomear, padrão e aninhado
▼
js — destructuring 
const usuario = {
  nome: "Anderson",
  idade: 22,
  endereco: { cidade: "Florianópolis" }
};

// Básico — extraindo propriedades
const { nome, idade } = usuario;
console.log(nome, idade); // "Anderson" 22

// Renomeando — cria variável com outro nome
const { nome: nomeUsuario } = usuario;
console.log(nomeUsuario); // "Anderson"

// Valor padrão — usado quando propriedade não existe
const { nome: nomeB, ativo = true } = usuario;
console.log(ativo); // true — não existe no objeto, usa padrão

// Nested destructuring — extraindo de objetos aninhados
const { endereco: { cidade } } = usuario;
console.log(cidade); // "Florianópolis"

// Muito usado em parâmetros de função
function exibir({ nome, idade }) {
  console.log(`${nome} tem ${idade} anos`);
}

exibir(usuario); // "Anderson tem 22 anos"

Spread Operator (...)

O operador spread ... expande as propriedades de um objeto dentro de outro. É a forma recomendada para copiar, adicionar propriedades e unir objetos de forma imutável. Atenção: o spread faz apenas cópia superficial (shallow copy):

Operação Sintaxe Resultado
Copiar objeto { ...usuario } Nova referência com mesmas propriedades
Adicionar propriedade { ...usuario, idade: 22 } Cópia + nova propriedade
Sobrescrever valor { ...usuario, nome: "Carlos" } Cópia com nome alterado
Unir objetos { ...obj1, ...obj2 } Todas as propriedades combinadas
🌀 Exemplos — spread: copiar, sobrescrever, unir e shallow copy
▼
js — spread operator 
const usuario = { nome: "Anderson", idade: 22 };

// Copiando objeto
const copia = { ...usuario };
console.log(copia); // { nome: "Anderson", idade: 22 }

// Adicionando propriedade sem alterar o original
const comEmail = { ...usuario, email: "a@email.com" };
console.log(usuario);  // { nome: "Anderson", idade: 22 } — intacto!
console.log(comEmail); // { nome: "Anderson", idade: 22, email: "a@email.com" }

// Sobrescrevendo valor
const atualizado = { ...usuario, idade: 23 };
console.log(atualizado); // { nome: "Anderson", idade: 23 }

// Unindo dois objetos
const dadosBasicos = { nome: "Anderson" };
const contato = { email: "anderson@email.com" };
const completo = { ...dadosBasicos, ...contato };
console.log(completo); // { nome: "Anderson", email: "anderson@email.com" }

// ⚠️ Shallow copy — objetos aninhados são referências!
const original = { nome: "Ana", endereco: { cidade: "Floripa" } };
const rasa = { ...original };

rasa.endereco.cidade = "São José";
console.log(original.endereco.cidade); // "São José" — afetou o original!

Object.keys(), Object.values() e Object.entries()

Esses três métodos estáticos permitem inspecionar e percorrer objetos de formas complementares. São especialmente úteis quando você precisa iterar sobre as propriedades de um objeto sem saber seus nomes com antecedência:

Object.keys()
Retorna as propriedades
Retorna um array com os nomes das chaves do objeto.

Object.keys(usuario)
→ ["nome", "idade"]
Object.values()
Retorna os valores
Retorna um array com os valores de cada propriedade.

Object.values(usuario)
→ ["Anderson", 22]
Object.entries()
Retorna chave e valor
Retorna um array de pares [chave, valor] — ideal para percorrer com for...of.

Object.entries(usuario)
→ [["nome","Anderson"],["idade",22]]
🔬 Exemplos — keys, values, entries e percorrendo objetos
▼
js — Object.keys, values, entries e iteração 
const usuario = { nome: "Anderson", idade: 22 };

// Object.keys() — retorna as chaves
console.log(Object.keys(usuario));
// ["nome", "idade"]

// Object.values() — retorna os valores
console.log(Object.values(usuario));
// ["Anderson", 22]

// Object.entries() — retorna pares [chave, valor]
console.log(Object.entries(usuario));
// [["nome", "Anderson"], ["idade", 22]]

// Percorrendo com for...of + destructuring
for (const [chave, valor] of Object.entries(usuario)) {
  console.log(`${chave}: ${valor}`);
}
// nome: Anderson
// idade: 22

Imutabilidade com Objetos

Assim como nos arrays, a abordagem imutável é preferida em React e aplicações modernas. Em vez de alterar o objeto original, crie um novo com as modificações usando o spread operator:

⚠️ Mutável
Modifica o objeto original
A atribuição direta altera o objeto existente. Em React, o estado não é detectado como alterado, causando bugs de renderização.

usuario.nome = "Carlos" // altera o original
✅ Imutável
Cria um novo objeto
O spread copia tudo e sobrescreve apenas o que mudou, preservando o original. É o padrão exigido em React com useState.

const novo = { ...usuario, nome: "Carlos" }

Boas Práticas

Nomes significativos
Nomeie com clareza
Use nomes que descrevam a entidade. usuario, produto, pedido — não x ou obj.

const produto = { nome: "Notebook" };
Destructuring
Extraia o que precisar
Prefira destructuring a acessar repetidamente pela notação de ponto. O código fica mais limpo e legível.

const { nome, email } = usuario;
Sem aninhar demais
Evite estruturas muito profundas
Objetos muito aninhados dificultam manutenção. Se necessário, considere achatar ou reorganizar a estrutura.

a.b.c.d.e.f // ⚠️ evite
🚀 As regras de ouro dos Objetos: use notação de ponto para acessar e colchetes apenas quando a propriedade for dinâmica; prefira destructuring para extrair múltiplas propriedades; use o spread operator para atualizar de forma imutável — { ...obj, propriedade: novoValor }; itere com Object.entries() + for...of; e lembre que o spread faz shallow copy — objetos aninhados ainda são referências compartilhadas.
Glossário

📖 Glossário

Os principais termos técnicos que você irá encontrar constantemente no desenvolvimento com JavaScript.

JavaScript
Linguagem de programação interpretada, executada no navegador, responsável pela lógica, interatividade e dinamismo das páginas web.
Variável
Espaço nomeado na memória para armazenar um valor. Em JS moderno, declarada com let (mutável) ou const (imutável).
Função
Bloco de código reutilizável que executa uma tarefa específica. Pode receber parâmetros e retornar valores.
DOM
Sigla para Document Object Model. Representação em árvore do HTML que o JavaScript usa para ler e modificar a página em tempo real.
Evento
Ação do usuário ou do sistema (clique, tecla, scroll) que pode ser capturada com addEventListener para executar código.
Array
Lista ordenada de valores. Declarada com colchetes: []. Suporta métodos como push, map, filter e find.
Objeto
Estrutura de dados com pares chave-valor. Declarada com chaves: {}. Representa entidades do mundo real no código.
Promise
Objeto que representa o resultado eventual de uma operação assíncrona — podendo ser resolvida (sucesso) ou rejeitada (erro).
async / await
Sintaxe moderna para trabalhar com código assíncrono de forma legível, evitando o encadeamento de .then().
fetch
API nativa do navegador para fazer requisições HTTP e consumir dados de APIs externas, retornando uma Promise.
JSON
Sigla para JavaScript Object Notation. Formato de texto leve para troca de dados entre cliente e servidor.
Callback
Função passada como argumento para outra função, executada após a conclusão de uma operação.
Escopo
Contexto em que uma variável existe e pode ser acessada. Pode ser global, de função ou de bloco (let e const).
Hoisting
Comportamento do JS de mover declarações de variáveis e funções para o topo do escopo antes da execução.
Event Loop
Mecanismo que permite ao JavaScript executar operações assíncronas em uma única thread, processando a fila de callbacks.
Closure
Função que "lembra" do escopo em que foi criada, mesmo após esse escopo ter encerrado a execução.
