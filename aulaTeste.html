🎯 Objetivos da Aula

Compreender o que é HTML — entender que HTML é a linguagem responsável por estruturar o conteúdo das páginas web e por que todo site começa com <!DOCTYPE html>.

Dominar a estrutura base do documento — aprender o papel do <html>, <head>, <body>, <meta>, <title> e como o navegador interpreta cada parte.

Seção 01

O que é
HTML?

Toda página que você acessa na internet — o Instagram, o YouTube, a Netflix — começa com HTML. É ele quem diz ao navegador o que exibir na tela: títulos, textos, imagens, botões e links. Sem HTML, não existe web.

O que significa HTML?

HTML significa HyperText Markup Language — em português, Linguagem de Marcação de Hipertexto. É a linguagem responsável por estruturar o conteúdo das páginas web. Pense nela como o esqueleto de um site: sem HTML, não há títulos, textos, imagens nem links.

📌 O HTML é chamado de linguagem de marcação porque usamos marcações chamadas tags para identificar cada parte da página, como títulos, textos, imagens e links.
🏠 Analogia

Se um site fosse uma casa, o HTML seria a estrutura — paredes, portas, janelas e cômodos. O CSS seria a pintura e decoração. O JavaScript seria a automação elétrica e a campainha.

Você pode ter uma casa sem pintura, mas não pode ter uma casa sem paredes. Da mesma forma, todo site precisa de HTML — os outros são complementos.

O que o HTML faz e o que ele não faz

Entender os limites do HTML é essencial para não se confundir com CSS e JavaScript. Cada tecnologia tem sua responsabilidade dentro de uma página web.

✅ HTML FAZ
→Cria títulos, subtítulos e parágrafos
→Insere imagens e links
→Organiza seções e formulários
→Define a estrutura semântica da página
→Conecta CSS e JavaScript ao documento
❌ HTML NÃO FAZ
→Estilização visual (isso é CSS)
→Animações e efeitos visuais (CSS/JS)
→Lógica e interatividade avançada (JavaScript)
→Banco de dados ou autenticação (Back-end)
→Processamento no servidor (linguagens Back-end)
💡 No projeto Pearl Jam que vamos construir, o HTML cria toda a estrutura: o <nav>, o <section id="hero">, os cards da discografia e os botões. O CSS cuida do visual e o JavaScript das interações.
Seção 02

Estrutura Base do
Documento HTML

Todo arquivo HTML começa com a mesma base. Entender cada linha dessa estrutura é o primeiro passo para escrever código que o navegador interpreta corretamente em qualquer dispositivo.

Destrinchando cada parte da estrutura

Cada linha da estrutura base tem um propósito específico. Remover qualquer uma delas pode causar problemas de renderização, acessibilidade ou SEO. Veja o que cada parte significa.

🧠 O navegador interpreta o HTML de cima para baixo.
Por isso, a organização da estrutura influencia diretamente carregamento, SEO, estilos e scripts.
01
<!DOCTYPE html>
Informa ao navegador que o documento usa HTML5. Sem ele, o navegador entra em "modo de compatibilidade" e pode interpretar a página de forma errada — especialmente em versões antigas do Internet Explorer.
doctype 
<!DOCTYPE html>
02
<html lang="pt-BR">
É o elemento raiz do documento HTML — toda a aplicação fica dentro dele, incluindo o <head> e o <body>. O atributo lang="pt-BR" define o idioma principal da página, melhorando acessibilidade para leitores de tela, SEO e tradução automática.
lang 
<html lang="pt-BR">
    <!-- aplicação -->
</lang>
03
<head>
Contém metadados e configurações da página. Nada dentro do <head> aparece diretamente para o usuário, mas tudo aqui influencia SEO, carregamento de fontes, CSS e configuração mobile.
head 
<head>
    <!-- metadados e configurações -->
</head>
04
<meta charset="UTF-8" />
Define a codificação de caracteres. Sem UTF-8, acentos e caracteres especiais são exibidos incorretamente. João pode virar JoÃ£o se esse meta estiver ausente.
charset 
<meta charset="UTF-8" />
05
Viewport Responsiva
Sem esse meta, o site fica minúsculo no celular. Ele garante que a página se adapte corretamente ao tamanho da tela, sem zoom automático estranho ou layout quebrado.
viewport 
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
06
<title> — Título da Aba
Define o texto exibido na aba do navegador, nos favoritos e nos resultados do Google. É um dos elementos mais importantes para SEO.
title 
<title>Pearl Jam — Ten Club Tribute</title>
07
Linkando CSS e Importando Fontes
O <link> conecta o arquivo CSS ao HTML. Com o atributo rel="stylesheet" e href apontando para o arquivo. Google Fonts também é importado via <link>.
link — css e fontes 
<!-- CSS próprio -->
<link rel="stylesheet" href="style.css" />

<!-- Fonte do Google Fonts -->
<link
  href="https://fonts.googleapis.com/css2?family=Bebas+Neue&display=swap"
  rel="stylesheet"
/>
08
Script JavaScript com defer
O <script> importa o JavaScript. O atributo defer garante que o script só execute após o HTML ser lido completamente, evitando erros de elementos não encontrados.

Antigamente, era comum colocar o <script> no final do <body> para evitar problemas de carregamento. Hoje, o uso de defer dentro do <head> é uma das abordagens mais utilizadas.
script defer 
<script src="script.js" defer></script>

Estrutura completa do Pearl Jam

Agora que você já entende a função de cada parte da estrutura, veja como tudo isso se organiza em um documento HTML completo. Essa será a base inicial do projeto Pearl Jam que vamos construir.

index.html — estrutura base completa 
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Pearl Jam — Ten Club Tribute</title>
    <link rel="stylesheet" href="style.css" />
    <script src="script.js" defer></script>
  </head>
  <body>
    <!-- Conteúdo da página vai aqui -->
  </body>
</html>
📦 Resumindo

Todo documento HTML segue uma estrutura base. O navegador precisa dessa organização para interpretar corretamente o conteúdo da página.

Depois dessa estrutura pronta, começamos a construir o conteúdo visual dentro da tag <body>.

Seção 03

A Tag
<body>

Tudo que o usuário vê na tela vive dentro do <body>. Textos, imagens, botões, menus, cards, vídeos e seções fazem parte dessa área. É dentro dela que construímos toda a interface visual de uma página web.

O que existe dentro do <body>?

O <body> funciona como a área visível da página. Tudo que aparece para o usuário no navegador precisa estar dentro dessa tag: títulos, textos, imagens, menus, botões, cards, formulários e seções do site.

📝
Textos e Títulos
Todo conteúdo textual — <h1>, <h2>, <p> — fica no body e é renderizado diretamente na tela.
🖼️
Imagens e Mídia
Tags como <img>, <video> e <audio> inserem conteúdo multimídia visível ao usuário.
🔗
Links e Botões
Elementos de interação como <a> e <button> ficam no body para que o usuário clique e navegue.
🧩
Seções e Layouts
Toda estrutura visual — <nav>, <section>, <footer>, <div> — organiza o conteúdo dentro do body.

Exemplos reais dentro do <body>

Tudo que vimos nos cards agora aparece funcionando em um exemplo real. Observe como títulos, imagens, links e seções ficam organizados diretamente dentro da tag <body>.

body 
<body>
  <h1>Pearl Jam</h1>    
  <p>
    Banda de rock formada em Seattle.
  </p>
  <img
    src="show.jpg"
    alt="Show do Pearl Jam"
  />
  <a
    href="#discografia">
    Ver Discografia
  </a>
</body>
👀 Perceba que todos os elementos visíveis estão dentro do <body>.
Se um conteúdo estiver fora dele, o navegador pode ignorar ou interpretar incorretamente a estrutura da página.
⚠️ Lembre-se:
O <head> contém configurações invisíveis ao usuário.
O <body> contém tudo que aparece na tela.
Colocar um <link> de CSS dentro do body tecnicamente funciona, mas é considerado uma má prática.
Seção 03

Atributos de Controle
e Agrupamento

HTML sozinho define apenas a estrutura da página. Mas como o CSS sabe qual elemento estilizar? E como o JavaScript sabe qual elemento manipular? É aqui que entram os atributos id e class, além das tags de agrupamento <div> e <span> — os verdadeiros “controles remotos” da interface.

Os atributos id e class

Esses atributos funcionam como nomes e identificadores dos elementos HTML. Eles criam “ganchos” para o CSS aplicar estilos e para o JavaScript localizar elementos na página.

🆔 id
→ Identificador único da página
→ Não deve se repetir
→ Usado para âncoras, JavaScript e seções específicas
→ CSS seleciona usando #nome
🏷️ class
→ Pode ser reutilizada em vários elementos
→ Ideal para estilos repetidos
→ Permite criar componentes visuais reutilizáveis
→ CSS seleciona usando .nome
id e class 
<!-- id: único na página -->
<section
  id="discografia"
>

<!-- class: reutilizável -->
  <div
    class="album-card"
  >

    <h3>Ten</h3>

  </div>

</section>

As caixas <div> e <span>

Essas tags não possuem significado semântico próprio. Elas existem para agrupar elementos e criar pontos de controle para CSS e JavaScript.

📦 <div>
→ Elemento de bloco
→ Ocupa toda a largura disponível
→ Usado para estruturar layouts e seções
✏️ <span>
→ Elemento inline
→ Não quebra linha
→ Usado para estilizar partes específicas do texto
div e span 
<div class="card">

  <h3>
    Pearl <span class="highlight">Jam</span>
  </h3>

  <p>
    Banda formada em Seattle em 1990.
  </p>

</div>
🎮 Analogia prática

Pense no HTML como uma casa:

O id funciona como o número único da residência. Já a class funciona como categorias: “quartos”, “janelas”, “portas”.

A <div> é uma caixa grande usada para organizar ambientes. O <span> é como um marcador pequeno dentro de um texto.

Sem id e class, CSS e JavaScript ficariam “cegos”, sem saber em qual elemento agir.

⚠️ Evite criar nomes genéricos como class="div1" ou class="teste". Prefira nomes descritivos como album-card, hero-title ou footer-links.
Seção 05

Tipografia e
Hierarquia

O conteúdo de uma página é comunicado através de texto. HTML oferece um conjunto de tags que não apenas formata o texto, mas define sua importância, ênfase e estrutura lógica — dando voz e ordem ao que o usuário lê.

Tags de Títulos — <h1> a <h6>

O HTML oferece seis níveis de título. O <h1> é o mais importante da página — deve existir apenas um por página e descrever o tema principal. Os demais criam uma hierarquia de subtítulos, como capítulos e seções de um livro.

⚠️ Não pule níveis de heading por questões visuais. Se precisar de um texto menor, use CSS. Pular de <h1> para <h4> prejudica acessibilidade e SEO.
headings — h1 a h6 
<h1>Pearl Jam — Ten Club Tribute</h1>   <!-- título principal da página -->
<h2>Discografia</h2>                     <!-- seção de nível 2 -->
<h3>Álbuns dos anos 90</h3>               <!-- subseção de nível 3 -->
<h4>Ten (1991)</h4>                       <!-- agrupamento menor -->
<h5>Faixas principais</h5>
<h6>Curiosidades</h6>

Parágrafos e Texto Inline

O <p> cria blocos de texto (elementos de bloco). Já <strong>, <em> e <span> são elementos inline — funcionam dentro de um parágrafo sem quebrá-lo, adicionando ênfase ou marcação semântica.

📋 Tag
→<p> — parágrafo de texto
→<strong> — importância semântica (negrito)
→<em> — ênfase sutil (itálico)
→<span> — marcação sem semântica própria
→<br> — quebra de linha
→<hr> — linha divisória temática
✅ Exemplo real
<p>
  O álbum <strong>Ten</strong> foi lançado
  em <em>27 de agosto de 1991</em>
  e é considerado um dos maiores
  discos do grunge.
  Vendeu mais de
  <span class="destaque">
    13 milhões de cópias
  </span>
  nos Estados Unidos.
</p>

Listas: <ul>, <ol> e <li>

Listas organizam itens relacionados. A diferença fundamental: <ul> é para itens sem ordem específica (como ingredientes), enquanto <ol> é para itens com ordem importa (como passos de instalação). Todo item de lista usa <li>.

ul, ol e li 
<!-- Lista não ordenada: membros da banda -->
<ul>
  <li>Eddie Vedder — vocal</li>
  <li>Mike McCready — guitarra</li>
  <li>Stone Gossard — guitarra</li>
  <li>Jeff Ament — baixo</li>
</ul>

<!-- Lista ordenada: passo a passo -->
<ol>
  <li>Clone o repositório</li>
  <li>Crie o arquivo index.html</li>
  <li>Publique no GitHub Pages</li>
</ol>
🗂️ Regra de ouro

Use <strong> quando o conteúdo tiver importância semântica real (como um alerta ou nome de produto). Use CSS font-weight: bold quando for apenas estilo visual. O mesmo vale para <em> vs CSS font-style: italic.

<span> é o "canivete suíço" inline — sem semântica própria, serve apenas para aplicar classes CSS ou selecionar partes do texto com JavaScript.

Seção 06

Links e
Navegação

A tag <a> (âncora) é o que torna a web uma teia de conexões. Com ela conectamos páginas, seções, arquivos e endereços externos — criando a navegação que o usuário percorre ao explorar um site.

A tag <a> e seus atributos

O elemento âncora tem um atributo essencial — o href (Hypertext REFerence) — que define o destino do link. Mas existem outros atributos que controlam o comportamento da navegação e a segurança do link.

Atributo Valor(es) comuns Função
href "https://...", "#id", "pagina.html" Define o destino do link — obrigatório para navegação funcionar
target "_blank", "_self" _blank abre em nova aba; _self abre na mesma aba (padrão)
rel "noopener", "noreferrer" Segurança: evita que a nova aba acesse a janela original via JavaScript
download "arquivo.pdf" Força o download do arquivo ao invés de abri-lo
title "Descrição do link" Tooltip exibido ao passar o mouse; útil para acessibilidade

Tipos de links

01
Link Externo
Aponta para outra URL na internet. Sempre use target="_blank" com rel="noopener noreferrer" por segurança — sem isso, a nova aba pode manipular a página original.
link externo 
<a
  href="https://pearljam.com"
  target="_blank"
  rel="noopener noreferrer"
>
  Site oficial do Pearl Jam
</a>
02
Âncora Interna
O href com #id leva o usuário para uma seção específica da mesma página — útil em menus de navegação como o do nosso projeto Pearl Jam.
âncora interna 
<!-- Link no menu -->
<a href="#discografia">Discografia</a>

<!-- Seção de destino (mais abaixo na página) -->
<section id="discografia">
  <h2>Discografia</h2>
</section>
03
Links Especiais
O href aceita protocolos especiais: mailto: para abrir o cliente de e-mail, tel: para discagem no celular, e caminhos relativos para arquivos locais do projeto.
links especiais 
<!-- Abre cliente de e-mail -->
<a href="mailto:contato@pearljam.com">Enviar e-mail</a>

<!-- Discagem direta no celular -->
<a href="tel:+5548999990000">Ligar agora</a>

<!-- Download de arquivo -->
<a href="setlist.pdf" download>Baixar Setlist</a>
💡 Um link com href="#" não leva a lugar nenhum — rola a página para o topo. Para links sem destino definido ainda, prefira href="javascript:void(0)" ou use um <button> com CSS, que é semanticamente mais correto para ações.
Seção 06

Estrutura
Semântica

HTML semântico significa usar a tag certa para o conteúdo certo. Não é apenas estética de código: é acessibilidade, SEO, organização e manutenção profissional.

O que é HTML semântico?

Antes do HTML5, desenvolvedores usavam <div> para praticamente tudo. O HTML5 trouxe tags com significado — como <nav>, <section>, <article> e <footer> — que descrevem a função de cada parte da página, não apenas sua aparência.

📰 Analogia — Jornal

Imagine um jornal impresso: ele tem um cabeçalho, seções temáticas, artigos individuais e um rodapé. O HTML semântico funciona exatamente assim — cada tag descreve o papel daquela parte, tornando a página compreensível para humanos, buscadores e leitores de tela.

Por que usar?

O impacto vai além da organização do código. HTML semântico beneficia três áreas fundamentais:

SEO
Melhor indexação
Mecanismos de busca como o Google entendem a hierarquia do conteúdo com mais precisão, o que pode melhorar o posicionamento nos resultados de pesquisa.
Acessibilidade
Leitores de tela
Tecnologias assistivas usam as tags para anunciar regiões da página. Um <nav> é anunciado como "navegação"; um <div> não diz nada.
Manutenção
Código legível
Qualquer desenvolvedor que abrir o código entende a estrutura imediatamente, sem precisar decifrar camadas de <div>s aninhados.

Semântico vs não semântico

Ambos os exemplos abaixo funcionam visualmente, mas apenas um descreve corretamente o significado do conteúdo.

❌ Não Semântico
<div>
  <div>Menu</div>    
  
  <div>
    <div>Conteúdo 01</div>
    <div>Conteúdo 02</div>       
  </div>
      
  <div>Rodapé</div>
</div>
✅ Semântico
<header>
  <nav>Menu</nav>
</header>
      
<main>
  <section>Conteúdo 01</section>
  <section>Conteúdo 02</section>
</main>
      
<footer>Rodapé</footer>

Tags semânticas mais utilizadas

Conheça as principais tags semânticas do HTML5 e quando usar cada uma delas.

Tag Função Quando usar
<header> Cabeçalho da página ou seção Logotipo, título, navegação principal
<nav> Bloco de navegação Menus principais, paginação, índices
<main> Conteúdo principal da página Único por página; envolve o conteúdo central
<section> Seção temática do conteúdo Blocos com tema próprio; sempre com um título
<article> Conteúdo independente e reutilizável Posts, notícias, cards, comentários
<aside> Conteúdo lateral ou complementar Barras laterais, dicas, links relacionados
<footer> Rodapé da página ou seção Direitos autorais, contatos, links extras
<figure> Conteúdo visual com legenda Imagens, diagramas, trechos de código ilustrativos
<figcaption> Legenda do <figure> Sempre dentro de um <figure>
<time> Data ou horário legível por máquinas Datas de publicação, eventos, agendas
🧠 Quando estiver em dúvida entre <section> e <div>, pergunte-se: "esse bloco tem um tema próprio e um título?" Se sim, use <section>. Se for apenas agrupamento visual, use <div>.
Seção 07

Imagens e
Mídia

Imagens, vídeos e áudios enriquecem o conteúdo visual de uma página. Mas além de inserir mídia, o HTML exige atenção à acessibilidade — garantindo que todos os usuários, incluindo os que usam leitores de tela, tenham uma experiência completa.

🖼️
<img src="show.jpg" alt="Show do Pearl Jam" />
🎬<video controls>
<source src="show.mp4" type="video/mp4">

A tag <img> e o atributo alt

A tag <img> é um elemento vazio (sem tag de fechamento separada). O atributo src define o caminho da imagem e o alt fornece uma descrição textual — obrigatória para leitores de tela e exibida quando a imagem falha ao carregar.

🚫 Nunca omita o atributo alt. Para imagens decorativas sem significado semântico, use alt="" (string vazia) — isso instrui o leitor de tela a ignorá-la. Mas para imagens de conteúdo, sempre descreva o que está sendo exibido.
img — atributos essenciais 
<!-- Imagem com alt descritivo (conteúdo) -->
<img
  src="eddie-vedder.jpg"
  alt="Eddie Vedder durante show do Pearl Jam em Seattle, 1992"
  width="800"
  height="600"
  loading="lazy"
/>

<!-- Imagem decorativa (alt vazio) -->
<img src="textura-fundo.png" alt="" />

<figure> e <figcaption>

Quando uma imagem precisa de legenda, o HTML semântico recomenda envolver tudo em <figure> e usar <figcaption> para a legenda. Isso cria uma relação explícita entre imagem e texto, compreendida por buscadores e leitores de tela.

figure e figcaption 
<figure>
  <img
    src="ten-album.jpg"
    alt="Capa do álbum Ten do Pearl Jam"
  />
  <figcaption>
    Ten (1991) — álbum de estreia que vendeu mais de 13 milhões de cópias.
  </figcaption>
</figure>

Vídeo e Áudio Nativos

O HTML5 trouxe suporte nativo a <video> e <audio> sem precisar de plugins externos. O atributo controls exibe os controles padrão do navegador; autoplay inicia automaticamente (use com cuidado); e múltiplos <source> garantem compatibilidade entre navegadores.

🎬 Vídeo
<video
  controls
  width="100%"
  poster="capa-video.jpg"
>
  <source
    src="show.mp4"
    type="video/mp4"
  />
  <source
    src="show.webm"
    type="video/webm"
  />
  Seu navegador não suporta vídeo.
</video>
🎵 Áudio
<audio controls>
  <source
    src="even-flow.mp3"
    type="audio/mpeg"
  />
  <source
    src="even-flow.ogg"
    type="audio/ogg"
  />
  Seu navegador não suporta áudio.
</audio>
📌 O atributo loading="lazy" em imagens adia o carregamento até que a imagem se aproxime da viewport — melhora significativamente o desempenho em páginas com muitas imagens. Sempre informe width e height para evitar layout shift durante o carregamento.
Seção 08

Gráficos
Vetoriais — SVG

SVG (Scalable Vector Graphics) é uma linguagem de marcação para descrever gráficos vetoriais diretamente no HTML. Diferente de imagens rasterizadas (JPG, PNG), gráficos SVG nunca perdem qualidade ao ser ampliados — são matematicamente perfeitos em qualquer resolução.

Por que usar SVG?

Ícones, logotipos, ilustrações e gráficos em SVG têm tamanho de arquivo reduzido, podem ser estilizados com CSS, animados com JavaScript e são acessíveis por leitores de tela. São a escolha certa para qualquer elemento gráfico que precise ser responsivo.

📐
Escalável
Define formas com coordenadas matemáticas. Amplie para qualquer tamanho sem perda de qualidade — ideal para telas retina e 4K.
🎨
Estilizável com CSS
Atributos como fill, stroke e opacity podem ser sobrescritos por CSS, permitindo temas dinâmicos como dark/light mode.
⚡
Leve e performático
Um ícone SVG simples pode ter menos de 1KB. PNG equivalente pode ter 20KB. Em páginas com muitos ícones, a diferença é significativa.
♿
Acessível
Com <title> e aria-label dentro do SVG, leitores de tela conseguem interpretar e anunciar o conteúdo gráfico.

Tags e atributos essenciais

01
<svg> — o contêiner
Todo SVG começa aqui. O viewBox define o sistema de coordenadas interno; width e height definem o tamanho no layout. Definir apenas viewBox e controlar o tamanho via CSS é a abordagem mais responsiva.
svg container 
<svg
  viewBox="0 0 100 100"
  xmlns="http://www.w3.org/2000/svg"
  width="200"
  height="200"
>
  <!-- formas aqui -->
</svg>
02
Formas básicas: <circle>, <rect>, <line>
As formas primitivas do SVG. Coordenadas referem-se ao sistema interno do viewBox.
circle, rect, line 
<!-- Círculo: cx, cy = centro; r = raio -->
<circle cx="50" cy="50" r="40" fill="#e44d26" />

<!-- Retângulo: x, y = canto superior-esquerdo -->
<rect x="10" y="10" width="80" height="80" rx="8" fill="none" stroke="#38bdf8" stroke-width="2" />

<!-- Linha: coordenadas de início e fim -->
<line x1="0" y1="0" x2="100" y2="100" stroke="#facc15" stroke-width="2" />
03
<polygon> e <path>
<polygon> conecta uma lista de pontos formando um polígono fechado. <path> é o mais poderoso — permite desenhar qualquer forma com comandos como M (mover), L (linha), C (curva bezier) e Z (fechar).
polygon e path 
<!-- Triângulo com polygon -->
<polygon
  points="50,10 90,90 10,90"
  fill="rgba(228,77,38,0.3)"
  stroke="#e44d26"
  stroke-width="2"
/>

<!-- Curva com path -->
<!-- M = move to | Q = quadratic bezier | Z = close -->
<path
  d="M 10,50 Q 50,10 90,50 Z"
  fill="none"
  stroke="#38bdf8"
  stroke-width="2"
/>
🎯 SVG inline vs arquivo externo

SVG pode ser usado de duas formas: inline (colado diretamente no HTML, dentro de <svg></svg>) ou como arquivo externo via <img src="icone.svg">.

SVG inline permite controle total via CSS e JavaScript — ideal para ícones interativos e animações. SVG externo via <img> é mais simples, mas perde a capacidade de ser estilizado dinamicamente.

Tabelas de
Dados

Tabelas HTML são para dados tabulares — informações que fazem sentido em linhas e colunas, como planilhas. Não foram feitas para layout visual. Usadas corretamente, tornam dados complexos legíveis e acessíveis.

Álbum Ano Cópias
Ten199113M
Vs.19937M
Vitalogy19946M

Anatomia de uma tabela HTML

Uma tabela bem estruturada usa elementos semânticos para separar cabeçalho, corpo e rodapé. Isso melhora a acessibilidade e permite que navegadores e leitores de tela interpretem corretamente a relação entre dados e seus rótulos.

01
<table> — o contêiner
Envolve toda a tabela. Internamente, organiza-se em <thead>, <tbody> e opcionalmente <tfoot>. Essa separação é semântica — o visual é controlado por CSS.
02
<thead> e <th> — cabeçalhos
<thead> agrupa as linhas de cabeçalho. Dentro dele, <th> (table header) representa uma célula de cabeçalho — semanticamente diferente de <td>. Leitores de tela anunciam o <th> antes de cada célula de dado correspondente.
03
<tbody>, <tr> e <td> — dados
<tbody> agrupa as linhas de dados. Cada linha é um <tr> (table row). Cada célula é um <td> (table data). Para mesclar células, use colspan (colunas) ou rowspan (linhas).
tabela completa — discografia Pearl Jam 
<table>
  <thead>
    <tr>
      <th>Álbum</th>
      <th>Ano</th>
      <th>Produtora</th>
      <th>Cópias vendidas</th>
    </tr>
  </thead>

  <tbody>
    <tr>
      <td>Ten</td>
      <td>1991</td>
      <td>Epic Records</td>
      <td>13 milhões</td>
    </tr>
    <tr>
      <td>Vs.</td>
      <td>1993</td>
      <td>Epic Records</td>
      <td>7 milhões</td>
    </tr>
  </tbody>

  <tfoot>
    <tr>
      <td colspan="3">Total estimado</td>
      <td>85 milhões</td>
    </tr>
  </tfoot>

</table>
🚫 Nunca use tabelas para layout visual. Antes do CSS, era comum usar <table> para organizar colunas e sidebars. Hoje isso é má prática grave: quebra acessibilidade, dificulta responsividade e aumenta a complexidade desnecessariamente. Para layouts, use CSS Flexbox ou Grid.

Formulários e
Interatividade

Formulários são a principal forma de coletar informações do usuário. Login, cadastro, busca, contato, compra — tudo passa por um <form>. Construí-los corretamente envolve semântica, acessibilidade e usabilidade juntos.

A estrutura de um <form>

O elemento <form> agrupa todos os campos. Os atributos action (para onde enviar) e method (GET ou POST) definem o comportamento do envio. Sem action, o formulário envia para a própria URL.

form — estrutura base 
<form action="/enviar" method="POST">

  <!-- Label + Input: sempre associados pelo atributo for/id -->
  <label for="nome">Nome completo</label>
  <input
    type="text"
    id="nome"
    name="nome"
    placeholder="Ex: Eddie Vedder"
    required
  />

  <label for="email">E-mail</label>
  <input type="email" id="email" name="email" required />

  <label for="mensagem">Mensagem</label>
  <textarea id="mensagem" name="mensagem" rows="5"></textarea>

  <button type="submit">Enviar mensagem</button>

</form>

O atributo type do input define o comportamento e a validação automática do campo. Usar o tipo correto melhora a experiência no mobile (abre teclado numérico, de e-mail, etc.) e ativa validação nativa do navegador sem JavaScript.

<select> — Menu de seleção

select e option

meta description — A descrição no Google

A meta description é o texto exibido abaixo do título nos resultados de busca. Não é um fator de ranking direto, mas influencia a taxa de clique (CTR). Deve ter entre 150 e 160 caracteres e descrever o conteúdo de forma atraente.

meta description e keywords 
<head>
  <title>Pearl Jam — Ten Club Tribute</title>

  <!-- Descrição exibida nos resultados do Google -->
  <meta
    name="description"
    content="Site tributo ao Pearl Jam com discografia completa, letras e história da banda de Seattle fundada em 1990."
  />

  <!-- Autor da página -->
  <meta name="author" content="Anderson Dutra" />

</head>

Quando alguém cola um link no WhatsApp, Instagram ou Twitter, a plataforma busca as OG tags (Open Graph) para montar o card de visualização — imagem, título e descrição. Sem elas, o compartilhamento aparece genérico ou sem imagem.

open graph tags 
<!-- Open Graph: controla como a página aparece ao ser compartilhada -->

<!-- Twitter Card (mesmo conceito, prefixo diferente) -->
<meta name="twitter:card"        content="summary_large_image" />
<meta name="twitter:title"       content="Pearl Jam — Ten Club Tribute" />
<meta name="twitter:description" content="Discografia, letras e história do Pearl Jam." />
<meta name="twitter:image"       content="https://seusite.com/og-cover.jpg" />

Favicon — O ícone da aba

O favicon é o ícone exibido na aba do navegador, nos favoritos e na tela inicial do celular quando o usuário salva o site. Hoje o padrão é fornecer múltiplos formatos para diferentes contextos.

🎯 Head completo do projeto Pearl Jam

Agora que você conhece todas as meta tags, veja como fica o <head> completo do projeto — com charset, viewport, title, favicon, OG tags e o link do CSS. Esse é o padrão profissional que você vai usar em todos os seus projetos a partir de agora.

  <meta charset="UTF-8" />

  <!-- 2. Título da página -->
  <title>Pearl Jam — Ten Club Tribute</title>

  <!-- 3. SEO -->
  <meta name="description" content="Discografia, letras e história do Pearl Jam." />
  <meta name="author" content="Anderson Dutra" />

  <!-- 4. Open Graph -->
  <meta property="og:title"       content="Pearl Jam — Ten Club Tribute" />
  <meta property="og:description" content="Discografia, letras e história do Pearl Jam." />
  <meta property="og:image"       content="https://seusite.com/og-cover.jpg" />

🧠 Resumindo

O <head> é a identidade invisível da sua página. Ninguém vê diretamente, mas ele controla como o Google te encontra, como o WhatsApp exibe seu link, qual ícone aparece na aba e como o site se comporta no celular.

Trate o <head> com o mesmo cuidado que trata o conteúdo visível — ele é a diferença entre um site amador e um projeto profissional.

Seção 05

Tags
Essenciais

Estas são as tags que você vai usar em praticamente todo projeto web. Dominar cada uma delas — incluindo seus atributos mais comuns — é o alicerce do front-end.

O que são tags?

Tags são os blocos de construção do HTML. Elas são escritas entre < e > e dizem ao navegador o que cada elemento é e como deve ser interpretado. A maioria das tags tem abertura e fechamento — a tag de fechamento leva uma barra: </tag>.

🧱 Analogia — Construção

Pense nas tags como os materiais de uma construção. O <h1> é a viga principal — única e estrutural. O <p> são as paredes. O <a> são as portas que conectam ambientes. E o <div> é o cômodo que agrupa tudo.

Por que dominar cada uma?

Usar a tag errada funciona — mas traz consequências silenciosas. Uma imagem sem alt quebra a acessibilidade. Um <h1> duplicado prejudica o SEO. Um link sem rel="noopener" abre uma brecha de segurança. Conhecer as tags vai além da sintaxe: é entender o impacto de cada escolha.

Sintaxe
Estrutura correta
Tags abertas precisam ser fechadas (exceto as vazias como <img>). Aninhamento errado quebra o layout e confunde o navegador.
Atributos
Comportamento extra
Atributos como href, src, alt e class complementam a tag com informações essenciais para o funcionamento e a acessibilidade.
Boas práticas
Impacto real
Cada tag carrega convenções. Respeitá-las garante compatibilidade entre navegadores, melhor SEO e um código que outros desenvolvedores conseguem entender e manter.

Visão geral das tags essenciais

Antes de explorar cada uma em detalhe, veja o mapa completo das tags desta seção.

Tag Tipo Função Atributos principais
<h1> … <h6> Bloco Títulos e subtítulos class, id
<p> Bloco Parágrafos de texto class, id
<a> Inline Links internos e externos href, target, rel
<img> Vazio Imagens src, alt, width, height
<ul> / <ol> Bloco Listas não ordenadas / ordenadas class, type
<li> Bloco Item de lista class, value
<div> Bloco Container genérico de bloco class, id
<span> Inline Container genérico inline class, id
<strong> Inline Texto com importância semântica (negrito) —
<em> Inline Texto com ênfase semântica (itálico) —
🧠 Tags de bloco ocupam a largura total e empurram o próximo elemento para baixo. Tags inline ficam no fluxo do texto. Entender essa diferença é essencial para controlar o layout com CSS.

Cada tag em detalhe

Explore cada tag abaixo. Veja como funciona, quando usar e um exemplo real do projeto.

🔤 Títulos — <h1> até <h6>
▼

Os títulos criam hierarquia visual e semântica. O <h1> é o mais importante — deve existir apenas um por página. Os demais (h2 a h6) são usados para subtítulos e subdivisões.

Boa prática: use os títulos em ordem crescente. Nunca pule de h1 para h4 sem passar por h2 e h3 — isso quebra a acessibilidade e o SEO.

títulos no Pearl Jam 
<h1 class="hero-title">
        Pearl <span class="highlight">Jam</span>
      </h1>
      
      <h2 class="section-title">Shows Inesquecíveis</h2>
      
      <h3>Setlist — São Paulo 2022</h3>
📄 Parágrafos — <p>
▼

A tag <p> é usada para blocos de texto corrido. O navegador adiciona automaticamente margem superior e inferior. Use para descrições, legendas e qualquer texto que forme um parágrafo completo.

Atenção: não use <br> para simular espaçamento entre parágrafos. Use <p> corretamente e controle o espaço via CSS.

parágrafo 
<p class="hero-subtitle">
        More than a band — a movement.
      </p>
🔗 Links — <a>
▼

A tag <a> cria hyperlinks. O atributo href define o destino. Para links internos (mesma página), use #id-da-secao. Para links externos, use a URL completa com target="_blank" e rel="noopener" por segurança.

links — interno e externo 
<!-- Link interno (mesma página) -->
      <a href="#discography" class="btn btn-primary">
        Explorar Discografia
      </a>
      
      <!-- Link externo (abre nova aba) -->
      <a
        href="https://pearljam.com"
        target="_blank"
        rel="noopener"
      >
        Site Oficial ↗
      </a>
🖼️ Imagens — <img>
▼

A tag <img> é uma tag vazia — não tem fechamento. O atributo src define o caminho da imagem e o alt define o texto alternativo, essencial para acessibilidade e SEO.

Nunca omita o alt. Leitores de tela usam esse texto para descrever a imagem. Para imagens puramente decorativas, use alt="" para que sejam ignoradas.

imagem 
<img
        src="./img/eddie.png"
        alt="Eddie Vedder, vocalista do Pearl Jam"
        width="400"
        height="500"
      />
📋 Listas — <ul>, <ol> e <li>
▼

O <ul> cria uma lista não ordenada (marcadores). O <ol> cria uma lista ordenada (numerada). Os itens de ambas sempre usam a tag <li>.

Boa prática: menus de navegação são tecnicamente listas de links — usar <ul> dentro do <nav> é a forma semanticamente correta.

listas no Pearl Jam 
<!-- Lista não ordenada -->
      <ul>
        <li>Eddie Vedder</li>
        <li>Mike McCready</li>
        <li>Stone Gossard</li>
      </ul>
      
      <!-- Lista ordenada -->
      <ol>
        <li>Ten (1991)</li>
        <li>Vs. (1993)</li>
        <li>Vitalogy (1994)</li>
      </ol>
📦 Divisões — <div> e <span>
▼

O <div> é um container genérico de bloco — ocupa a largura total. Usado para agrupar elementos, criar layouts e aplicar estilos via CSS.

O <span> é um container inline — não quebra a linha. Perfeito para estilizar trechos específicos de texto sem alterar o fluxo do conteúdo.

div e span 
<!-- div: container de bloco -->
      <div class="card">
        <h2>Ten</h2>
        <p>Álbum de estreia do Pearl <span class="highlight">Jam</span></p>
      </div>
✍️ Ênfase — <strong> e <em>
▼

O <strong> marca texto com importância semântica — renderizado em negrito pelo navegador. O <em> indica ênfase — renderizado em itálico. Ambos têm significado para leitores de tela, diferente de <b> e <i>, que são apenas visuais.

ênfase semântica 
<p>
        O álbum <strong>Ten</strong> vendeu mais de
        <em>13 milhões de cópias</em> nos EUA.
      </p>
🧠 Prefira sempre <strong> e <em> no lugar de <b> e <i>. O resultado visual é o mesmo, mas a versão semântica comunica significado — não apenas estilo.
Seção 06

Listas em HTML

Listas são essenciais para menus de navegação, itens de conteúdo e agrupamento de informações. O HTML oferece dois tipos principais: não ordenada e ordenada.

📋 Lista Não Ordenada — <ul>

Itens sem ordem específica. O navegador exibe com marcadores (bullets). Muito usada em menus de navegação.

ul + li 
<ul class="nav-links">
  <li><a href="#shows">Shows</a></li>
  <li><a href="#members">Integrantes</a></li>
  <li><a href="#disco">Discografia</a></li>
</ul>
🔢 Lista Ordenada — <ol>

Itens com sequência numérica. Usada quando a ordem importa — como passos de um tutorial ou ranking.

ol + li

  <li>Vs. (1993)</li>
  <li>Vitalogy (1994)</li>
</ol>

Seção 07

Classes e IDs

Classes e IDs são atributos que conectam o HTML ao CSS e ao JavaScript. Sem eles, você não consegue estilizar elementos específicos nem criar interações com JavaScript.

🏷️ class — Múltiplos elementos
→Pode ser usada em vários elementos ao mesmo tempo
→No CSS: .hero-title { ... }
→Um elemento pode ter múltiplas classes: class="btn btn-primary"
→Usado para estilização e reutilização
🔑 id — Identificador único
→Deve ser único na página — não repita IDs
→No CSS: #hero { ... }
→No HTML: <a href="#discography"> leva à seção
→No JS: document.getElementById("hero")

Boas práticas de nomenclatura

❌ Evite
✗class="coisa1"
✗class="box2"
✗id="item123"
✗class="vermelho" (cor no nome)
✅ Use
✓class="hero-title"
✓class="album-card"
✓id="discography"
✓class="carousel-track"
Seção 08

Anatomia de um Elemento HTML

Todo elemento HTML segue a mesma estrutura. Entender cada parte — tag, atributos, conteúdo e fechamento — é fundamental para escrever código correto e sem erros.

anatomia completa 
<a href="#discography" class="btn">
  Explorar Discografia
</a>
Tag de abertura
<a ...>
Inicia o elemento. Contém o nome da tag e, opcionalmente, os atributos. O navegador lê isso e sabe que tipo de elemento vai renderizar.
Atributos
href="#discography"
Informações adicionais do elemento no formato nome="valor". Definem comportamento, destino, estilo, acessibilidade e muito mais.
Conteúdo
Explorar Discografia
O que fica entre as tags de abertura e fechamento. Pode ser texto, outras tags HTML, imagens ou qualquer outro conteúdo.
Tag de fechamento
</a>
Encerra o elemento com a barra /. Toda tag que tem conteúdo precisa ser fechada. Tags vazias como <img> e <meta> são auto-fechadas.
⚠️ Tags vazias não têm conteúdo e não precisam de fechamento separado: <img />, <meta />, <br />, <input />. Já <div>, <p>, <a> sempre precisam da tag de fechamento </tag>.
Seção 09

Como o Navegador interpreta a página

Quando você acessa um site, o navegador executa uma sequência de etapas bem definida. Entender esse fluxo ajuda a escrever código mais eficiente e evitar bugs clássicos.

1
Lê o HTML
O navegador faz o download do arquivo index.html e começa a ler linha por linha, de cima para baixo.
2
Monta o DOM
O navegador transforma o HTML em uma árvore de objetos chamada DOM (Document Object Model). Cada tag vira um nó nessa árvore.
3
Carrega e processa o CSS
O arquivo style.css é baixado e aplicado ao DOM. Cores, fontes, tamanhos e layouts são calculados para cada elemento.
4
Executa o JavaScript
Com o atributo defer, o script.js é executado depois que o HTML foi completamente lido — evitando erros de "elemento não encontrado".
5
Renderiza a página visualmente
Finalmente, o navegador "pinta" a página na tela — calculando posições, aplicando estilos e exibindo o resultado que o usuário vê.

Seção 11

Boas Práticas

Escrever HTML que funciona é diferente de escrever HTML bem feito. As boas práticas a seguir são o que separa um código amador de um código profissional.

🧱
Use HTML Semântico
Prefira <nav>, <section>, <article>, <footer> a um mar de <div> sem significado. O código comunica sua intenção.
🔖
Nomeie Classes Corretamente
Use nomes descritivos: hero-title, album-card, carousel-track. Evite coisa1, box2, item123. O nome deve descrever o papel do elemento.
💬
Comente e Organize
Use comentários <!-- HERO --> para separar seções. Indente o código corretamente. Código organizado é mais fácil de manter e de compartilhar em equipe.
♿
Não Esqueça o alt
Sempre adicione o atributo alt em imagens. Ele descreve a imagem para leitores de tela e aparece quando a imagem não carrega.
ℹ️ Organização de Pastas: mantenha index.html na raiz, style.css e script.js ao lado, e crie uma pasta img/ para todas as imagens. Estrutura organizada = projeto profissional.

📖 Glossário HTML

HTML
HyperText Markup Language — linguagem de marcação que estrutura o conteúdo das páginas web.
Tag
Marcação HTML delimitada por < e >. Pode ter abertura, fechamento e conteúdo entre elas.
Atributo
Informação extra dentro da tag de abertura, no formato nome="valor". Ex: href, src, alt.
DOM
Document Object Model — representação em árvore que o navegador cria a partir do HTML para renderizar a página.
Semântica
Uso de tags com significado real (<nav>, <section>, <footer>) em vez de <div> genérico para tudo.
UTF-8
Codificação de caracteres que suporta acentos, emojis e caracteres especiais de todas as línguas.
Viewport
Área visível da tela. O meta viewport garante que o site se adapte corretamente ao tamanho do dispositivo.
defer
Atributo do <script> que faz o JavaScript carregar sem bloquear o HTML, executando após o DOM estar pronto.
