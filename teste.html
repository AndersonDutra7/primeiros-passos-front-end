🎯 Objetivos da Aula

Compreender o que é CSS — entender que CSS é a linguagem responsável pela aparência visual das páginas e como ela trabalha em conjunto com o HTML para separar estrutura de estilo.

Dominar seletores e a cascata — aprender como selecionar elementos por tag, classe e ID, entender a especificidade e como o CSS decide qual regra vence quando há conflito.

Trabalhar com cores, tipografia e espaçamentos — aplicar propriedades fundamentais como color, font-family, margin, padding e o poderoso Box Model.

Criar layouts modernos com Flexbox e Grid — construir estruturas responsivas e profissionais usando os dois sistemas de layout mais utilizados no mercado.

Animar e tornar responsiva a página — aplicar transições, animações com @keyframes, media queries e variáveis CSS para criar uma experiência visual completa e profissional.

Seção 17

📖 Glossário

Os principais termos técnicos que você irá encontrar constantemente no desenvolvimento web com CSS.

CSS
Sigla para Cascading Style Sheets. É a linguagem responsável pela apresentação visual das páginas web, controlando cores, fontes, espaçamentos e layouts.
Seletor
Parte da regra CSS que indica quais elementos serão estilizados. Exemplos: p, .classe, #id.
Propriedade
Característica visual que será alterada, como color, font-size ou margin.
Valor
O dado atribuído a uma propriedade CSS. Exemplo: color: red — onde red é o valor.
Box Model
Modelo que descreve como cada elemento HTML ocupa espaço, composto por content, padding, border e margin.
Flexbox
Sistema de layout unidimensional que permite alinhar e distribuir elementos em linhas ou colunas com facilidade.
Grid
Sistema de layout bidimensional que organiza elementos em linhas e colunas ao mesmo tempo, ideal para estruturas complexas.
Variáveis CSS
Valores reutilizáveis definidos com --nome no :root e acessados via var(--nome). Facilitam manutenção e consistência visual.
Media Query
Regra CSS que aplica estilos condicionalmente com base no tamanho da tela ou dispositivo, fundamental para responsividade.
Especificidade
Regra que determina qual estilo prevalece quando múltiplos seletores atingem o mesmo elemento. IDs têm maior peso que classes, que têm maior peso que tags.
Cascata
Mecanismo que define a ordem de aplicação dos estilos CSS, considerando especificidade, herança e ordem de declaração.
Pseudo-classe
Seletor que aplica estilos em estados específicos do elemento, como :hover, :focus e :nth-child.
Pseudo-elemento
Permite estilizar partes específicas de um elemento, como ::before, ::after e ::first-line.
Transição
Propriedade transition que anima suavemente a mudança entre dois estados CSS, como uma mudança de cor ao passar o mouse.
Herança
Mecanismo pelo qual propriedades CSS de um elemento pai são transmitidas automaticamente aos elementos filhos, como font-family e color.
Reset CSS
Conjunto de regras que remove os estilos padrão do navegador, garantindo consistência visual entre diferentes browsers.

Seção 02

Como conectar
JavaScript

Antes de escrever uma linha de código, você precisa saber como o navegador carrega o JavaScript. A forma como você inclui o <script> na página determina a ordem de execução, o desempenho e até se o código vai funcionar corretamente — ou não.

As três formas de incluir JavaScript

Existem três maneiras de conectar JavaScript a um documento HTML. Cada uma tem seu caso de uso — mas na prática profissional, uma delas domina:

Inline
Diretamente no elemento
Código JS escrito dentro de atributos do HTML como onclick="...". Mistura estrutura e comportamento no mesmo lugar — evite sempre que possível. Dificulta manutenção e impede reutilização.
Interno
Dentro da tag <script>
Código JS escrito diretamente no HTML, entre tags <script></script>. Útil para scripts pequenos e específicos de uma página. Não é reutilizável em outros arquivos.
Externo ✅
Arquivo .js separado
O código fica em um arquivo .js independente, referenciado pelo atributo src. É a abordagem profissional: separa responsabilidades, permite cache do navegador e reutilização em múltiplas páginas.
comparação visual — as três formas de incluir JS
❌ Inline
<button onclick="alert('oi')" >Clique</button>
🟡 Interno
<script> const x = 1; </script>
✅ Externo
<script src="script.js" defer ></script>

Onde posicionar o <script>

A posição do <script> no HTML tem impacto direto na ordem de carregamento e na experiência do usuário. O navegador processa o HTML de cima para baixo — e para tudo quando encontra um <script> sem atributos especiais:

<head>
⚠️ <script src="..."></script> — bloqueia o HTML antes de renderizar
<body>
… conteúdo da página (HTML) …
</body>
✅ <script src="..."></script> — HTML já carregou, DOM disponível
💡 Colocar o <script> antes do </body> era a solução clássica para garantir que o DOM estivesse pronto. Hoje, os atributos defer e async permitem manter o script no <head> sem bloquear o carregamento — e com controle total sobre a ordem de execução.

defer e async — o carregamento inteligente

Esses dois atributos mudam como e quando o script é baixado e executado em relação ao parsing do HTML. Entender a diferença é fundamental para escrever páginas performáticas:

defer ✅ recomendado
Baixa em paralelo, executa depois
O script é baixado em paralelo com o parsing do HTML, mas só executa depois que o documento inteiro foi lido. A ordem entre múltiplos scripts é preservada. Use sempre que o script precisar acessar o DOM ou depender de outro script.
async — use com cuidado
Baixa em paralelo, executa imediatamente
O script é baixado em paralelo, mas executa assim que termina o download — interrompendo o HTML se necessário. A ordem não é garantida. Ideal apenas para scripts totalmente independentes, como analytics e tracking.

<!-- ❌ 1. Inline — evitar -->
<button onclick="alert('Evite isso!')">Clique</button>

<!-- 🟡 2. Interno — para scripts pequenos e únicos -->
<script>
  const titulo = document.querySelector('h1');
  titulo.textContent = 'Olá, JavaScript!';
</script>

<!-- ✅ 3. Externo com defer — padrão recomendado -->
<script src="script.js" defer></script>

<!-- Múltiplos scripts com defer: ordem garantida -->
<script src="utils.js"   defer></script>  <!-- executa 1º -->
<script src="app.js"     defer></script>  <!-- executa 2º -->
<script src="main.js"    defer></script>  <!-- executa 3º -->

<!-- async: para scripts totalmente independentes -->
<script src="analytics.js" async></script>

Estrutura de arquivos recomendada

Com scripts externos, a organização dos arquivos passa a importar. Uma estrutura clara facilita manutenção e escalabilidade do projeto:

📁 meu-projeto/
├── 📄 index.html
├── 📁 css/
│ └── 📄 style.css
└── 📁 js/
├── 📄 utils.js ← funções auxiliares
├── 📄 components.js ← componentes de UI
└── 📄 main.js ← ponto de entrada ← carregado por último
📐 Exemplo completo — HTML com scripts externos e defer
▼
index.html — estrutura completa com scripts externos 
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Meu Projeto</title>

  <!-- CSS: sem defer, carrega normalmente -->
  <link rel="stylesheet" href="css/style.css">

  <!-- JS com defer: baixa em paralelo, executa na ordem -->
  <script src="js/utils.js"      defer></script>
  <script src="js/components.js" defer></script>
  <script src="js/main.js"       defer></script>

  <!-- Analytics: independente, pode usar async -->
  <script src="js/analytics.js"  async></script>
</head>
<body>

  <h1>Olá, mundo!</h1>
  <button id="btn">Clique aqui</button>

</body>
</html>
💡 Com defer, os scripts ficam no <head> mas o HTML não é bloqueado. O navegador baixa todos os arquivos .js em paralelo enquanto lê o HTML, e só executa cada script — na ordem declarada — após o documento estar completamente parseado. É o melhor dos dois mundos.

Impacto na performance

A forma como você carrega JavaScript afeta diretamente o tempo que o usuário espera para ver e interagir com a página. As métricas do navegador mais impactadas são:

FCP — First Contentful Paint
Tempo até o primeiro conteúdo
Scripts bloqueantes no <head> atrasam o FCP — o navegador para de renderizar até terminar de baixar e executar o JS. Com defer, o HTML renderiza normalmente e o FCP melhora de forma significativa.
TTI — Time to Interactive
Tempo até a página responder
O TTI mede quando a página está pronta para interação. defer garante que o JS executa só quando o DOM está pronto, evitando erros de elemento não encontrado e tornando a inicialização mais previsível.
Prática Impacto Recomendação
Script bloqueante no <head> Atrasa renderização inteira ❌ Evitar
Script no final do <body> HTML renderiza antes, mas download é tardio 🟡 Aceitável
defer no <head> Download paralelo + execução ordenada após HTML ✅ Padrão recomendado
async para scripts independentes Download paralelo + execução não bloqueante ✅ Para analytics e afins
Dividir em múltiplos arquivos pequenos Cache granular + downloads paralelos ✅ Em produção com bundler
🚀 A regra de ouro: use <script src="..." defer></script> no <head> para todos os scripts da sua aplicação. Reserve async apenas para scripts que não dependem do DOM e não dependem de outros scripts — como pixels de rastreamento e ferramentas de analytics.
